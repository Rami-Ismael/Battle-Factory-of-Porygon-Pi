Masked team completion · DSPy structure, phase one

Mask, fill, battle

A random legal Regulation M-B team loses some fields. A language model fills them. The completed team is checked, then plays the frozen meta pool. The experiment changes one thing: how the request and reply are structured.

Two Stat Point spreads are masked

Goodra and Scovillain lose their Stat Points (0–32 each, at most 66 in total). Both requests carry the same instructions and the same four values.

Baseline: one JSON message 
system Complete only the null fields…
       Return only JSON: {"fills":[…]}.
user   {"format": "gen9…regmb",
        "opponents": [49 pastes],
        "masked_team": [… {"species":
          "Goodra", "evs": null} …],
        "requested_paths":
          [[1,"evs"],[4,"evs"]]}
DSPy: typed fields 
system inputs: format, opponents,
         masked_team, requested_paths
       output: fills (list[Fill])
         + its JSON schema
       Complete only the null fields…
         (same text)
user   [[ ## masked_team ## ]]
       [… {"species": "Goodra",
           "evs": null} …]
       [[ ## requested_paths ## ]]
       [[1,"evs"],[4,"evs"]]

Model, provider, reasoning level, temperature 0.7 and output cap are identical. Only the reply-format sentence changes: DSPy's field layout and typed output replace “Return only JSON”.

The reply is parsed, then checked

An answer that cannot be read is rejected before any rule is checked. Rejected answers are never repaired or re-asked.
