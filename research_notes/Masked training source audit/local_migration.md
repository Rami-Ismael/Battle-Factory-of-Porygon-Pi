## How should fixed interval validation stop mid epoch?

### Takeaway
Reuse/extract the existing patience state machine, replace block validation with upstream-equivalent masked validation using fixed random draws, and check patience immediately at each configured update interval. Stop the whole training run mid epoch and deliver the best checkpoint.

### Cited Findings
- The local stopping skill requires searching for existing helpers, a seeded held-out split excluding test/top-50/meta-51-100 teams, 2% for corpus runs or 20% for small fine-tunes, common validation mask draws, patience 3, cap-sized LR schedule, best checkpoint restoration and full metadata. [skill lines 12-22](/Users/ramiismael/.claude/skills/early-stopping/SKILL.md:12).
- Skill says use five-fold cross validation if validation would hold fewer than about 100 rows; fixed-budget/reproduction exceptions still log validation. [skill 24-30](/Users/ramiismael/.claude/skills/early-stopping/SKILL.md:24).
- Search `rg -n patience code/src code/scripts` found an existing implementation in `diffusion84.Model84.train_new`: best-loss comparison, checkpoint callback, patience, restore and metadata. It is embedded in a scratch model loop, not a generic trainer callback. Reuse/extract its state logic rather than invoke scratch trainer for text model. [188-253](https://github.com/Rami-Ismael/Battle-Factory-of-Porygon-Pi/blob/dc8f91c5f97879d285f64da00d82476b1537edce/code/src/diffusion84.py#L188-L253).
- Main text trainer validates at `step % eval_every == 0`, cap/end conditions, saves each checkpoint, then always saves `final`; no best comparison/patience restore. [413-455](https://github.com/Rami-Ismael/Battle-Factory-of-Porygon-Pi/blob/dc8f91c5f97879d285f64da00d82476b1537edce/code/src/textdiff.py#L413-L455).
- Main validator resets seed 1 and order every call, but computes block loss. It averages batch-normalized masked-token loss weighted by rows, so this is not automatically the chosen masked trainer's global denominator. [458-478](https://github.com/Rami-Ismael/Battle-Factory-of-Porygon-Pi/blob/dc8f91c5f97879d285f64da00d82476b1537edce/code/src/textdiff.py#L458-L478).
- Existing data preparation reuses scratch `lossdown.splits` and filters heldout rows, rather than defining the new skill's fraction explicitly. Split provenance and exclusion need auditing for new masked data. [44-89](https://github.com/Rami-Ismael/Battle-Factory-of-Porygon-Pi/blob/dc8f91c5f97879d285f64da00d82476b1537edce/code/src/textdiff.py#L44-L89).

### Inferences
Proposed specification, not implementation:
1. Search done. Extract or extend existing best/patience state logic to a shared helper and map each evaluation interval to a recorded validation index. Record both update step and fraction of pass, so patience=3 means three complete configured evaluation intervals, not an unspecified three optimizer steps.
2. Build new seeded split from approved training rows only, enforce excluded team sets before split, save exact row IDs/hash, seed and fraction. Use the skill's 2%/20% rule or its five-fold rule if fewer than about 100 validation rows.
3. Set `eval_every_updates=K` before launch. Define update as optimizer step after gradient accumulation; record effective examples/update. Keep validation rows/order/padding/batches/mask rate draws/mask uniforms fixed and use a separate RNG or save/restore global CPU/CUDA RNG around validation. Switch model to eval for deterministic dropout behavior and then restore train; match upstream masked loss semantics rather than forcing the block train-mode path.
4. After every K updates and at cap: evaluate full held-out objective with fixed draws, accumulate numerator/denominator exactly as chosen masked trainer specifies, and log interval training loss plus validation loss. Strictly smaller finite validation loss resets bad-interval count and saves best. Otherwise increment it; stop when count reaches patience, default 3. Nonfinite losses should fail explicitly rather than qualify as improvement. Restore best at all normal exits and stop the outer epoch loop too.
5. Cap is a separate hard bound; LR schedule stays sized to it even if patience stops early. Main's nominal total ignores skipped overlength rows and optional max_steps, so derive a truthful cap/scheduler for new tokenization/filtering. [main batching 338-347](https://github.com/Rami-Ismael/Battle-Factory-of-Porygon-Pi/blob/dc8f91c5f97879d285f64da00d82476b1537edce/code/src/textdiff.py#L338-L347), [schedule 413-415](https://github.com/Rami-Ismael/Battle-Factory-of-Porygon-Pi/blob/dc8f91c5f97879d285f64da00d82476b1537edce/code/src/textdiff.py#L413-L415).
6. Save best/stopped update and validation index, cap, patience, K, split and RNG seeds, row/mask hashes, best validation loss, interval curves, checkpoint path/hash and stopping reason. Include entire rule and seeds in cache key and checkpoint name. Restore tokenizer/adapters or full parameters correctly; resume additionally restores optimizer/scheduler/RNG/patience state.
7. Validate checkpoint choice by later laptop battles, not loss alone, as skill line 36 requires. No battle or generation is authorized here.
