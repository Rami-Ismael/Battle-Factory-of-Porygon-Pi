# Core and Dream sampler source inspection

## What sampler implementations and modes does the code contain?

### Takeaway
A sampler is the procedure that asks a model for token scores, chooses token identities and positions, and repeats until its output is ready. Here masked sampling means filling holes marked by a special mask token. A schedule decides how many holes to fill. Confidence is a score used to choose which holes to fill first. Those definitions describe the inspected implementation, not a claim that all diffusion samplers work this way. [Core implementation](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/mdlm.py#L149-L230)

### Cited Findings
All upstream links below pin commit `ca176752fbceec49c6b4777a2c18ae88e4eb10ed`. Source was read as text in `/tmp/dllm-source.gFPxLj`; nothing from it was installed, imported or executed. No Python or model runs were used.

- Core exports exactly two concrete sampler classes, masked diffusion `MDLMSampler` and block diffusion `BD3LMSampler`. `BaseSampler` is abstract plumbing, not another algorithm. [Exports](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/__init__.py#L1-L16), [abstract base](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/base.py#L21-L49)
- Ordinary LLaDA uses `MDLMSampler`; there is no separate ordinary `LLaDASampler` in that pipeline's exports. BERT evaluation also uses `MDLMSampler`. [LLaDA evaluation](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/llada/eval.py#L18-L45), [LLaDA exports](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/llada/__init__.py#L1-L11), [BERT evaluation](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/bert/eval.py#L18-L43)
- `MDLMSampler` starts with a prompt and masked suffix. It processes suffix blocks from left to right but calls its model on the entire canvas at every reveal step. Within a block it proposes tokens, ranks only remaining masked positions by probability of the proposed token, and commits the scheduled top positions. Its `remasking="random"` mode ranks holes randomly instead. Despite the name, neither mode reopens already committed tokens. [Canvas/block scheduling](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/mdlm.py#L107-L177), [proposal/selection](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/mdlm.py#L186-L230)
- Masked diffusion defaults: 128 new tokens, `max_length=None`, block size 128, total requested steps 128, temperature 0, `remasking="low_confidence"`, stochastic transfer false, classifier-free guidance scale 0, guidance keep-token list none, token suppression lists none, right-shift false. Blocks count is ceiling of new-token length/block size; requested steps per block are ceiling of total requested steps/block count. [Config](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/mdlm.py#L16-L31), [budget](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/mdlm.py#L129-L158)
- Classifier-free guidance means also scoring an input whose prompt tokens are hidden, then amplifying the difference from that score. In masked diffusion this is a doubled batch in one model call, not necessarily two separately timed calls. [Guidance](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/mdlm.py#L164-L177)
- The shared helper returns unchanged logits at temperature 0; otherwise it converts the entire logits tensor to float64 and draws float64 random noise. This is important for an eventual Apple-silicon port, but this inspection does not establish whether the current backend can execute it. [Noise helper](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/utils.py#L72-L83)
- Block diffusion `BD3LMSampler` appends a block at a time. Its attention mask lets each block see earlier blocks and all positions within itself, but no future blocks. It recomputes a prefix key/value cache once per new block, then repeatedly calls the model on only the current block with a deep copy of that cache. It commits holes by the same confidence/random rules. [Attention](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/bd3lm.py#L59-L81), [prefix](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/bd3lm.py#L282-L319), [inner call](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/bd3lm.py#L365-L426)
- Block diffusion defaults: 128 new tokens, block size 32, steps 128, optional `steps_per_block=None`, temperature 0, low-confidence selection, stochastic transfer false, guidance 0, keep-token list none, right-shift false. Stops after a finished block contains EOS. Its `infill` raises `NotImplementedError`. [Config](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/bd3lm.py#L137-L151), [steps](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/bd3lm.py#L260-L264), [EOS and infill](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/bd3lm.py#L431-L453)
- The shared transfer schedule computes counts from the remaining masks, with deterministic rounding or binomial draws, then removes steps that transfer nothing. Thus `steps=128` does not establish 128 model evaluations. The default scheduler is linear; cosine is also implemented. A scheduler is a count rule, not another concrete sampler. [Transfer helper](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/utils.py#L28-L69), [default](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/base.py#L22-L29), [scheduler formulas](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/schedulers/alpha.py#L101-L116)

#### Dream confidence samplers
- `DreamSampler` supports three `alg` values. `maskgit_plus` ranks by probability of the sampled candidate; `topk_margin` ranks by the difference between the two most probable token identities; `entropy` ranks by negative entropy, preferring concentrated distributions. These are position selection rules within one sampler class, not three separate model families. [Dispatch](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/dream/sampler.py#L188-L234), [scores](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/dream/sampler.py#L16-L53)
- Token temperature controls which candidate token is chosen. At positive temperature Dream samples from probabilities after temperature scaling, top-p probability-mass filtering, then top-k vocabulary filtering; at nonpositive temperature it takes maximum probability. `alg_temp` separately randomizes which positions commit; zero means highest-score positions. Vocabulary `top_k` and choosing the top positions are different operations. [Token sampling](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/dream/sampler.py#L16-L53), [position sampling](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/dream/sampler.py#L218-L234), [filters](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/dream/models/generation_utils.py#L37-L55)
- Dream class defaults: 20 new tokens, steps 512, epsilon .001, `alg="origin"`, `alg_temp=0`, token temperature 1, top-p 1, vocabulary top-k 50, stochastic transfer false, right-shift true, guidance 0. IMPORTANT: default `origin` is not accepted by the class's dispatch, so the class defaults are inconsistent. `eps` is read but unused in the class's sampling loop. `infill` exists but unlike `sample`, its implementation does not use guidance scale. [Config](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/dream/sampler.py#L56-L71), [dispatch rejection](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/dream/sampler.py#L190-L211), [infill argument extraction and forward](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/dream/sampler.py#L309-L377)
- A separate Dream model method `diffusion_generate` really does implement `origin` inside `_sample`. For each remaining hole, independent random selection with probability `1-s/t` decides whether to fill; the last step fills all remaining holes. It also implements the same three confidence rules. Its defaults differ from `DreamSampler`: token temperature 0, top-p/k none, 512 steps, epsilon .001, origin algorithm. It always performs the requested loop count; unlike the shared transfer helper, it does not compact empty reveal steps. [Configuration](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/dream/models/generation_utils.py#L99-L110), [algorithm](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/dream/models/generation_utils.py#L406-L451)

#### Fast Dream
- `FastdLLMDreamSampler` accepts the same three confidence rules and an added `confidence_threshold`. Settings add `threshold=None`, `use_cache=None|"prefix"|"dual"`, block size 32; base defaults again say unsupported `alg="origin"`. There is no classifier-free guidance setting in this config. [Config](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/fastdllm/dream/sampler.py#L56-L71), [cache values](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/fastdllm/dream/sampler.py#L110-L115), [dispatch](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/fastdllm/dream/sampler.py#L162-L178)
- Without cache, its three ordinary modes follow full-canvas Dream sampling. Threshold mode instead proposes a scheduled candidate set plus deferred positions, filters candidates below threshold but always retains the highest-ranked one, then continues until no masks remain. `steps` is a schedule input, not a hard cap in this threshold loop. [Threshold loop](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/fastdllm/dream/sampler.py#L180-L255)
- With cache, Fast Dream divides generation into blocks. Each block begins with a full-canvas forward and fills its first position. Prefix cache keeps only earlier positions' keys/values and recomputes the current block plus later suffix; dual cache keeps the full cache and recomputes the current block while replacing its cache positions. This is an approximation for a bidirectional masked model because cached positions need not see later changed tokens. [Cache setup](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/fastdllm/dream/sampler.py#L305-L404)
- Cache mode requires generation length divisible by block size and requested steps divisible by block count. In cached nonthreshold modes, `steps_per_block` bounds the loop; in threshold mode reveal count depends on threshold and masks remaining, with a top-one fallback. Source includes an inner forward before the `inner_step == steps_per_block` break check, so a simple count of committed states does not equal forward calls. Cached threshold code operates on row zero when constructing selection and sums mask counts across the batch. Treat multirow threshold support as unverified. [Constraints](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/fastdllm/dream/sampler.py#L308-L321), [loop/threshold](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/fastdllm/dream/sampler.py#L396-L487)
- Fast Dream `infill` is unimplemented. Cache calls pass `dual_cache` and `replace_position` arguments, requiring a compatible model implementation rather than any masked model with a tokenizer. [Calls](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/fastdllm/dream/sampler.py#L396-L404), [infill](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/pipelines/fastdllm/dream/sampler.py#L494-L501)

### Inferences
- Applicability: generic masked diffusion needs a mask-predicting model with the expected tokenizer/logit conventions. The code demonstrates wiring to LLaDA, BERT and autoregressive-to-diffusion converted masked models. Block diffusion requires a model trained for the block attention convention and cache protocol. A fully bidirectional masked model can mechanically accept a restricted attention mask only if its forward API supports it; that does not validate generation quality. Dream requires the Dream call/logit alignment, or an explicitly adapted equivalent. Fast Dream's cache modes need its specialized backend. [Masked converted example](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/examples/a2d/mdlm/sample.py#L25-L41), [block converted example](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/examples/a2d/bd3lm/sample.py#L25-L41), plus source links above.
- A sampler with `block_size` is not necessarily a block-trained model. Masked diffusion's block setting changes reveal order while retaining the full-canvas model call; block diffusion changes attention and model calls. [Masked call](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/mdlm.py#L129-L177), [block call](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/bd3lm.py#L365-L381)
- For team generation, none of these confidence rules proves legality. Probability is a learned preference, not Showdown validation. Greedier selection may concentrate output; token sampling and randomized position order may broaden output, but neither establishes measured team diversity. Suppressing individual tokens cannot generally enforce relational rules such as species/move compatibility. These are research judgements, not measured outcomes.

### Gaps
No runtime correctness, M4 Pro backend support, seconds/team, joules/team, legality, diversity, or battle performance was measured. No paper benchmark claim was verified in this subtask. The sampler defaults inconsistency and batch-sensitive Fast Dream threshold branches are source findings, not reproduced bugs.

### Inferences
For a report table with one row per concrete sampler class, put all three confidence modes in the Dream row and Fast Dream's threshold/cache choices in its row. Add a separate row or note for Dream's original-reveal model method so it is not omitted by a class-only inventory.

For a batch of K teams, an accounting identity is wall seconds per team = batch wall time / K, before validation/rejection. Accepted legal distinct teams per second depends additionally on acceptance and duplicates. Source-level forward counts cannot supply those measurements.

## How does sampling differ from decoding?

### Takeaway
The sampler creates token IDs. Tokenizer decoding turns IDs into text. The project's decoder then parses the text into a team. The broader literature also calls the token-generation loop decoding, so define the project's narrower meaning before comparing.

### Cited Findings
- dLLM's sampler outputs a sequence tensor and optional history. Its trimming utility removes prompt and termination tokens, calls `tokenizer.decode`, and returns text. That code is a distinct stage after sampling. [Output](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/base.py#L10-L18), [trimming and text conversion](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/utils/sampling.py#L4-L52)

### Inferences
The next engineer should keep sampler settings separate from paste parsing and legality validation. A probability-ranked item token can still become a syntactically valid but illegal team combination.

### Gaps
Project-specific parser/decoder and reading-list inspection are assigned to another researcher. This subtask establishes the upstream token IDs to text stage only.
