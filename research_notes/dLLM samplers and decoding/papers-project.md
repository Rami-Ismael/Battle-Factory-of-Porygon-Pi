# Project terminology and reading list crosswalk

## What are a sampler and the project decoder?

### Takeaway
A sampler is the procedure that repeatedly asks a model for candidate tokens and decides which tokens to write into the partly filled sequence. Here a decoder means the later conversion of generated token IDs into text, parsing that text into six Pokémon slots, filling missing Stat Point spreads under the existing policy, and validating the resulting Showdown paste. They are different stages and both affect accepted teams per second.

### Cited Findings
- Project baseline checked at commit `dc8f91c5f97879d285f64da00d82476b1537edce`. Generation calls either the checkpoint's `generate` or local `generate_cfg`, then separately `tok.decode(..., skip_special_tokens=True)`. [textdiff.py lines 513–524](https://github.com/Rami-Ismael/Battle-Factory-of-Porygon-Pi/blob/dc8f91c5f97879d285f64da00d82476b1537edce/code/src/textdiff.py#L513-L524)

[textdiff_battle.py lines 70–107](https://github.com/Rami-Ismael/Battle-Factory-of-Porygon-Pi/blob/dc8f91c5f97879d285f64da00d82476b1537edce/code/src/textdiff_battle.py#L70-L107)

Existing values are block 32, sub-block 8, threshold 0.9, token temperature 1, top-p 1. ### Inferences
- Plain definitions for report: a token is a vocabulary ID, often a fragment of a word. A mask token marks an unknown position. A model is the learned score-producing network. A masked model learns to fill unknown positions using visible context. A fully bidirectional model can consult visible tokens on both sides; a block model can consult earlier completed blocks and the current block, according to its attention rules. A forward pass is one evaluation of that network. A sampler chooses both token values and positions to reveal, possibly replacing earlier tokens if explicitly supported. A scheduler decides how many positions to fill or how rates vary over steps. A tokenizer decoder turns IDs into characters. The project decoder then turns those characters into a structured team. Broader papers sometimes call the entire generation algorithm 'decoding'; scope the term locally.
- Token temperature changes which vocabulary item is proposed; selection order chooses which position is committed. These are separate choices. The local sampler's temperature scales scores before softmax and affects confidence too, so changing it need not leave position decisions unchanged.
- Example for parent drawing, with each bracket representing one illustrative token position, not an actual Qwen tokenization: `Pikachu @ [MASK]\n- [MASK]`. Propose `LightBall` at confidence .95 and `Protect` at .70; threshold .9 commits only the item. Result `Pikachu @ LightBall\n- [MASK]`. This is a teaching illustration, not a generated legal paste or a claim that the actual tokenizer uses those whole names.
- Conceptual cost per accepted legal team is total generation plus token decoding/parsing/validation time divided by accepted team count. For repeat draws under stable settings, rough expectation is raw draw time divided by acceptance probability, plus downstream cost. Unique accepted teams per second requires measuring duplicates and the chosen diversity definition as well. More passes may improve acceptance enough to pay for themselves or may simply cost more. Neither conclusion follows from pass count alone.
- The local guidance strength has a different numeric convention from upstream MDLMSampler: local `g=2` weights conditional scores by 2, whereas upstream `cfg_scale=2` weights them by 3. Compare equations rather than matching knob values. [upstream MDLM lines 164–173](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/mdlm.py#L164-L173)

### Gaps
- No runs were performed. Existing timing and legality observations in textdiff.md are historical results for those particular checkpoints, tokenizations, and settings, not timings or quality estimates for all upstream samplers.
- No evidence here establishes a winner for legality, six-species novelty, or diversity per second on the M4 Pro. A short example string does not verify VGC legality.

### Inferences
- Source names are dangerous here: `remasking` in the ordinary confidence sampler means discard uncommitted proposals or choose which masks to fill, not necessarily erase a previously committed token. The code's update condition is the deciding evidence.
- Confidence-guided commitment could help immediate token consistency, while committing easy fields first may limit downstream diversity. A paper's pass@k or image recall result cannot establish six-species novelty or legal-team throughput.
- ReMDM and newer revision methods are research candidates outside this repository inventory, not extra samplers to add to the shipped list.

### Gaps
- All eight sampling entries' primary abstract pages were retrieved. Full HTML was inspected for ReMDM, Two Temperatures, and Re-evaluating Confidence Remasking. The other five were checked at abstract level only; no claim to full-paper refutation.
- Cross-version caution: Two Temperatures arXiv v2 says COLM acceptance and Re-evaluating arXiv v2 says NeurIPS 2026, newer than local Reading List labels. Reading list was not edited.
- No external blog was reviewed as a recommendation. MDLM and ReMDM project pages have linked blogs, but their presence alone is not a recommendation to add them.
- Exact statistical reverse-kernel equivalence, asymptotic correctness, calibrated confidence, and statistical gains for this VGC dataset have not been verified.
- A separate terminology collision: a transformer 'decoder layer' is an internal neural-network layer, not the project output decoder. The local file uses that architectural term in `functional_forward`/training layout code. A model originally called decoder-only can be adapted to bidirectional or block attention; its architecture label does not tell us whether generated text has passed the Showdown parser or legality validator.
