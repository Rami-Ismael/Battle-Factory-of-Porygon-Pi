# Uniform-noise diffusion sampling: stopping, loss, and guidance

A uniform diffusion language model (UDLM) stops after a chosen number of reverse steps. It does not wait for empty fields or for its output to stop changing. Here the default is 128 steps, from time 1 to time 0.00001, and the sampler returns that last random sample. There is no extra final denoising pass or noise-removal switch in this sampling path. [configs/config.yaml:35–41](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/configs/config.yaml#L35-L41) [diffusion.py:1115–1209](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1115-L1209)

For `K = sampling.steps` and continuous-time training, the code builds `linspace(1, eps, K+1)` and uses `dt=(1-eps)/K`. Iteration `i=0,...,K-1` takes the posterior step from `t_i=1-i*dt` to `s_i=t_i-dt`. Thus its last network evaluation is at `eps+dt`, and the final state is at `eps`, up to floating-point arithmetic. There is no network evaluation at `eps` after the loop. The `T>0` branch additionally rounds the evaluation time to its training grid, so this formula describes the requested `T=0` UDLM. [diffusion.py:1126–1145](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1126-L1145) [diffusion.py:1204–1209](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1204-L1209)

The starting tokens are independent uniform integer draws over the model vocabulary. These are a full sequence of values already at initialization. [diffusion.py:855–862](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L855-L862) [diffusion.py:1121–1124](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1121-L1124)

Keep a third epsilon separate: the actual log-linear noise class has internal `eps=1e-3`, with `sigma(t)=-log(1-(1-eps)*t)`. The factory constructs `LogLinearNoise()` without arguments. Consequently the sampler uses `alpha(t)=exp(-sigma(t))=1-0.999*t`, including `alpha(1)=0.001`, even though it starts from an exactly uniform prior. This algebra is an **inference from the implementation**. It differs slightly from the ideal endpoint `alpha(1)=0` used to cancel the paper's prior loss. [noise_schedule.py:13–18](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/noise_schedule.py#L13-L18) [noise_schedule.py:134–153](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/noise_schedule.py#L134-L153) [diffusion.py:1152–1155](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1152-L1155) Paper §4.2, p. 6, “Prior Loss.”

### A2. Final denoising and noise removal

The final iteration samples the same reverse posterior as every earlier iteration and returns `xt`. There is no special transition to time zero, clean-token argmax, or final draw from a new clean-data prediction. There is also no `noise_removal` option in the checked main configuration or a noise-removal branch in `_diffusion_sample`; neither uniform nor absorbing sampling gets such an extra step here. [configs/config.yaml:35–41](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/configs/config.yaml#L35-L41) [diffusion.py:1115–1209](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1115-L1209) [diffusion.py:1230–1253](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1230-L1253) [diffusion.py:1290–1342](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1290-L1342)

The categorical sampling helper contains an `argmax`, but applies it after dividing probabilities by random exponential noise. It implements a random categorical draw, not a final deterministic maximum-probability decoding rule. [diffusion.py:30–34](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L30-L34) [diffusion.py:1245–1246](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1245-L1246)

**Inference for this port:** “every field has a value” cannot be its stopping criterion, because that is true of the uniform initial state too. A faithful port needs an explicit reverse-step budget independent of the number of team fields. The upstream loop updates distributions for the whole sequence on every step; it does not choose one field to fill. ### A3. No early stop; the cache only reuses predictions

There is no convergence test, “all tokens unchanged” break, or “all masks filled” break. Every invocation executes `range(sampling.steps)`. After each iteration, the code clears the cache if caching is disabled or `xs` differs from `xt`. If caching is enabled and the entire batch stays unchanged, it retains predictions for the next iteration. It still recomputes the posterior at the new times and samples again. [diffusion.py:1126–1145](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1126-L1145) [diffusion.py:1204–1209](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1204-L1209) [diffusion.py:1220–1246](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1220-L1246)

For classifier-free guidance (CFG), the retained objects are conditional and unconditional clean-token log-probabilities. [diffusion.py:1266–1269](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1266-L1269) [diffusion.py:1341–1342](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1341-L1342) The UDLM script disables caching while enabling time conditioning; the MDLM script does the opposite. [scripts/train_qm9_guidance.sh:51–66](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/scripts/train_qm9_guidance.sh#L51-L66) `_process_sigma` zeros the noise input only when time conditioning is off. ## B. The implementation pieces for a port

### B1. Uniform forward corruption

For one-hot clean token `x`, vocabulary size `N`, and uniform vector `u=1/N`, the forward marginal is

```text
q(z_t | x) = Cat(alpha_t*x + (1-alpha_t)*u).
```

Paper §2.1, Eq. 1, p. 3; §4.1, p. 5; Appendix A, Eq. 20, p. 17. `_forward_pass_diffusion` computes `sigma` and `move_chance=1-exp(-sigma)`. `_q_xt` independently selects positions with that probability, draws uniform vocabulary indices, and substitutes them at selected positions. The redraw can equal the original token; selecting a position for corruption does not require its value to change. [diffusion.py:460–476](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L460-L476) [diffusion.py:500–507](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L500-L507) Uniform `u` is initialized at [diffusion.py:103–120](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L103-L120).

### B2. Continuous-time loss and the reconstruction switch

The continuous-time negative evidence lower bound uses Eq. 18 for one token and Eq. 19 for a sequence. Its per-token integrand, with `i` the observed noisy category, is

```text
bar_x       = N*alpha_t*x       + (1-alpha_t)*1
bar_x_theta = N*alpha_t*x_theta + (1-alpha_t)*1

ell_t = alpha'_t/(N*alpha_t) * [
    N/bar_x[i] - N/bar_x_theta[i]
    - sum_{j != i} bar_x[j]/bar_x[i]
      * log(bar_x_theta[i]*bar_x[j] / (bar_x_theta[j]*bar_x[i]))
]
```

Paper §4.2, Eqs. 17–19, p. 6; Appendix A, Eqs. 26–36, pp. 17–19. The code maps directly to `x_bar`, `x_bar_theta`, `coeff`, `term1`, `term2`, and `diffusion_loss` in [diffusion.py:563–597](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L563-L597). The sum includes all categories in code; the `j=i` log term is zero, which explains its equivalence to the excluded-index sum. That equivalence is an **algebraic inference** from those lines and Eq. 18.

The loss asserts log-linear noise and hardcodes `alpha'_t=-1` and `alpha_t=1-t` with shape `B,1,1`. Its own TODO proposes replacing these by `-dsigma*exp(-sigma)` and `exp(-sigma)` for a generic schedule. This means the loss's hardcoded alpha differs slightly from the actual epsilon-adjusted corruption schedule described in A1. [diffusion.py:563–580](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L563-L580) [noise_schedule.py:142–153](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/noise_schedule.py#L142-L153)

`zero_recon_loss=True` excludes the clean-input time-zero cross-entropy from the returned total objective. It does **not** remove or rescale the continuous-time diffusion term. The reconstruction helper evaluates `forward(x0, sigma(0), cond)` and returns the negative log-probability of each original token. The helper still executes and its value is returned for logging even when the switch excludes it from the total. [diffusion.py:435–447](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L435-L447) [diffusion.py:598–614](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L598-L614)

The paper justifies zero reconstruction loss in the continuous-time limit by requiring `alpha(t_0)→1` and an input-copying boundary parameterization. It separately sets the prior loss to zero when `alpha(1)=0` and the model prior equals the limiting distribution. Those are theoretical boundary arguments, not a claim that the flag adds an input-copying rule to `forward`. ### B3. Reverse posterior and random update

Let `r=alpha_t/alpha_s`, `x_theta` be the predicted clean-token probability vector, and `z_t` the one-hot current category. The implemented reverse distribution is

```text
p_theta(z_s | z_t) = Cat(
    [N*alpha_t*x_theta*z_t + (r-alpha_t)*z_t
     + (alpha_s-alpha_t)*x_theta
     + (1-r)*(1-alpha_s)*u]
    / [N*alpha_t*<x_theta,z_t> + 1-alpha_t]
).
```

Products of vectors here are elementwise. This is paper §4.1, Eq. 15, p. 5, from the true posterior Eq. 14; Appendix A, Eqs. 24–25, p. 17. `_compute_posterior` implements it at [diffusion.py:356–381](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L356-L381). The ordinary sampler exponentiates the model's log-probabilities, supplies the two alpha values, and draws categorical `xs`. [diffusion.py:1220–1246](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1220-L1246) The frozen-token copy rule applies only to absorbing noise. ## C. Position-specific noise schedules

### What the sources state

- The paper's sequence objective sums over positions but writes a common scalar `alpha_t` and derivative `alpha'_t` in every summand. Its barred probability vectors also depend on that alpha. The denoiser can see the whole noisy sequence, while reverse token distributions factorize conditional on that sequence. Paper §4.2, Eq. 19, p. 6.
- The continuous-time integrand depends on the schedule in both the prefactor `alpha'_t/(N*alpha_t)` and the barred vectors, including their probability ratios. Appendix A derives these terms by differentiating the single-token posterior. Paper Eq. 18, p. 6; Appendix A, Eqs. 30–36, pp. 18–19.
- The implemented uniform loss hardcodes a shared `alpha_t=1-t` and `alpha'_t=-1`. The TODO explicitly identifies those as the parts to make generic. [diffusion.py:563–597](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L563-L597)
- `_compute_posterior` documents alpha inputs of shape `(B, [L | 1], 1)`, so its arithmetic can broadcast either position-specific values or one value per sequence. However, the actual sampler asserts one-dimensional sigma after removing a singleton dimension and reshapes movement probabilities to `(B,1,1)`. The model's `_process_sigma` also asserts a one-dimensional time/noise input. [diffusion.py:356–380](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L356-L380) [diffusion.py:1144–1156](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1144-L1156) [diffusion.py:328–343](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L328-L343)
- The paper's reported experiments all use log-linear schedules. It does not present an experiment with a distinct alpha schedule for every token position. Paper Appendix D.3, p. 28; Eq. 19, p. 6 uses shared schedule notation.

### Inferences, not reported results

If the same independent-token corruption construction is extended to a separate differentiable schedule `alpha_l(t)` for each position, applying the paper's single-token derivation position by position would replace both `alpha_t` and `alpha'_t` in each summand, including inside the barred vectors. Changing only a single common loss multiplier would not perform those substitutions. This is a proposed algebraic extension of Eq. 19 and Appendix A, not a position-specific objective validated in the paper.

A port with such schedules would also need matching forward corruption and reverse alpha pairs per position, and a decision about how the network receives the noise information. The current posterior helper's broadcast support alone does not implement that end-to-end change. This follows from the contrast between [diffusion.py:356–380](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L356-L380), [diffusion.py:500–507](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L500-L507), [diffusion.py:563–580](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L563-L580), and [diffusion.py:1144–1156](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1144-L1156). Neither these sources nor the paper establish an accuracy benefit, a specific weighting heuristic, or a correct team-specific schedule.
