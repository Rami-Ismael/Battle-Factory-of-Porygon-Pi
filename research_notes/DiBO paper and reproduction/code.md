# Released DiBO code audit

## What does the pinned implementation construct and train?

### Takeaway
The release implements both delimiter and natural boundary rendering and both similarity and random neighbors, with stage-specific masking. It does not implement missing-score training. Several literal implementation details differ from the paper's compact description.

### Cited findings
All code references below pin commit `601fef5d502d0088a32841a477cb221beff105ef`, retrieved 2026-11-05. A dedicated previously nonexistent directory was cloned, statically read, and never imported, installed or executed. `code-source-manifest.json` records file hashes; `sources/DiBO-code-text-601fef5.tar` preserves source/docs/config excerpts as a plain tar, excluding datasets and model assets.

- The delimiter strings are `|design-start|`, `|design-end|`, `|label-start|`, `|label-end|`. Natural rendering uses `Design:  ` with two spaces, a single-space design terminator, `Label: `, and an empty label terminator. Each prompt example has a design and label; the response contains `Response:\n` then only a design, without its score. [Dataset lines 14–17, 203–227, 329–358, 644–648](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/dataset/task_pool_dataset.py#L203-L227).
- Pool size defaults to 500, few-shot count seven, candidate neighbors 50, context/target ratio 0.8. Data comes sorted by oracle score. Pool entries are evenly spaced ranks across the available visible data; alternate random/high/low pool options exist. [Dataset lines 124–155](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/dataset/task_pool_dataset.py#L124-L155); [defaults lines 45–55](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/dataset/task_pool_dataset.py#L45-L55).
- The target subset is **not** simply the highest 20%. Code selects 100 rank-spaced entries within the 70%–95% band, exclusive of 95%, and puts every other selected pool entry into the context subset. With 500 entries this means candidates at indices 350–474 and only 100 of these 125 indices in target subset. [Dataset lines 164–185](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/dataset/task_pool_dataset.py#L164-L185).
- For each candidate response anchor, code filters context candidates to strictly lower label and earlier sorted index, ranks them by RBF similarity in normalized feature space, retains at most 50, and requires at least seven. The bandwidth is median pairwise Euclidean distance over the pool. Seven are uniformly sampled without replacement from the retained neighbors for normal pool sizes. Thus the target is sampled first, then suitable worse prompt examples are selected around it; it is not a search for a better response after fixing an arbitrary prompt. [Neighbor construction lines 384–419](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/dataset/task_pool_dataset.py#L384-L419); [sampling lines 239–260](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/dataset/task_pool_dataset.py#L239-L260); [bandwidth lines 556–573](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/dataset/task_pool_dataset.py#L556-L573).
- DA samples targets from all valid context plus target subset anchors; SFT samples only valid target-subset anchors. Both reuse the same pool, templates, strict-improvement rule, and dynamic sampling procedure. An infinite iterable generates new combinations repeatedly until the optimizer-step limit, not fixed corpus epochs. [Anchor selection lines 534–545](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/dataset/task_pool_dataset.py#L534-L545); [iteration lines 229–260](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/dataset/task_pool_dataset.py#L229-L260); [step termination trainer lines 290–291, 629–640](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/trainer_dllm.py#L629-L640).
- DA masks both prompt and response. SFT restores the prompt and masks only the response span. Special-token response span includes both design delimiters; natural-mode span excludes its boundary strings. Mask probability per example is `p=0.999*t`, `t~Uniform[0,1)`. For masked tokens the numerator is `sum CE/p`. DA divides this by all input-token positions; SFT divides it by the actual number of masked response positions, clamped to one. [Span lines 346–357](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/dataset/task_pool_dataset.py#L346-L357); [masking trainer lines 454–504](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/trainer_dllm.py#L454-L504); [numerator lines 26–52](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/trainer_dllm.py#L26-L52); [normalization lines 563–584](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/trainer_dllm.py#L563-L584).
- Missing scores have no documented sentinel or supported training path: bundle loading requires all named label arrays, pool construction immediately converts all labels to floats and uses min/max and score comparisons, rendering formats scores as floats. The validator checks array sizes/order but does not reject NaNs explicitly. A NaN is therefore not a supported unscored example and must not be assumed safely ignored. [Bundle load lines 38–49 and validation 174–188](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/dataset/task_bundle.py#L38-L49); [pool labels lines 124–158](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/dataset/task_pool_dataset.py#L124-L158).
- Best example: the globally highest selected pool entry is outside the SFT target band and belongs to context subset, but cannot appear in any DA/SFT prompt because no anchor is strictly better. It **can** be a DA response if it has seven worse neighbors. The highest selected target-band example is an ordinary eligible SFT response with worse prompt neighbors; it does not need anything better than itself. Therefore the premise “the best has no better target” reverses this construction. [Band/partition lines 164–185](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/dataset/task_pool_dataset.py#L164-L185); [strict filter 394 and anchor selection 534–545](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/dataset/task_pool_dataset.py#L384-L419).

### Inferences
- The 130,232 unscored Pokémon teams cannot be fed into this released DA dataset unchanged. A separate text-only reconstruction stream or explicit score-missing design would be new project work, not the paper's recipe. The 174,348 scored teams can supply ranked pairs after defining an appropriate team-similarity representation; the release only supports its four named benchmark tasks, so Showdown text is not a drop-in dataset.
- A global best team can teach improvement as a response paired with worse teams. There is no need to invent an even better response.

### Gaps
- No execution was used to establish runtime behavior on NaNs, memory, tokenizer assertions, checkpoint equivalence, dependencies or commands. Static code is the evidence.

## Can similarity and joint reconstruction be separated from delimiters, and where does paper differ?

### Takeaway
The mechanisms are modular in code. Natural rendering can retain similarity and joint DA loss; the release still adds the four unused delimiter entries to the model vocabulary. Paper statements about a strict target/context split and loss normalization need qualification.

### Cited findings
- `--special_token_type {special,natural}` and `--ablation_use_random_neighbors {d1-d2,random}` are independent CLI choices. Stages are independently selectable with `--stages da sft` or `--stages sft`; masking/loss does not inspect delimiter type. [CLI lines 20, 36–39](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/main.py#L20-L39); [trainer lines 471–504, 563–584](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/trainer_dllm.py#L471-L504).
- In natural mode pipeline loading still calls the loader without overriding `add_special_tokens=True`; it installs the four vocabulary tokens and resizes embeddings even though natural pair rendering does not use them. This is a rendering ablation rather than an exact unchanged-tokenizer arm. [Pipeline lines 237–240](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/pipeline.py#L237-L240); [loader lines 230–258, 269–284](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/model/dllm.py#L230-L284).
- Paper Appendix A.2 says target responses never appear as prompt context and describes lower/higher groups. Code DA uses context-subset designs as responses as well; D1 also contains top 5% pool ranks and low ranks. Within each particular pair the strict lower-label rule still prevents the response itself appearing in that prompt. This is a cross-corpus split discrepancy, not evidence that identical design is present twice within a pair. [Paper v3 Appendix A.2](https://arxiv.org/html/2603.17919v3#A2); [code band construction](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/dataset/task_pool_dataset.py#L164-L185); [anchor selector](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/dataset/task_pool_dataset.py#L534-L545).
- Paper Eqs. 3–4 print inverse-time weighted token sums without the release's stage-specific denominators. Code DA averages over all token positions and SFT divides by the *random masked count*. The latter is more than a fixed learning-rate rescale because denominator depends on the sampled mask. Code also caps mask probability at `0.999*t` rather than exactly `t`. [Paper v3 section 3 Eqs. 3–4](https://arxiv.org/html/2603.17919v3#S3); [code loss](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/trainer_dllm.py#L563-L584); [code corruption](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/trainer_dllm.py#L454-L469).
- Code uses exact-oracle relabeled morphology labels, retaining source task labels separately. This adds important detail to Appendix A.1's “original designs and corresponding scalar labels.” [Data README lines 24–31](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/data/README.md#L24-L31).

### Inferences
- A clean controlled test can keep neighbor identities, prompts, and DA/SFT stages fixed while changing boundary rendering. To isolate “adding token embeddings” too requires a loader change, because the CLI natural mode alone leaves those vocabulary rows present.
- The Table 3 SFT comparison is DA→SFT in both arms, with versus without special boundary rendering. Comparing SFT-only to DA→SFT answers another question.

### Gaps
- No released Table 3 experiment manifest ties these implementation choices to the historical eight runs. The static current code need not be byte-for-byte historical paper code.

## What is released and what commands are possible?

### Takeaway
The current release is substantially more complete than a code-only repository: it has prepared arrays, bundles, prompts, relabels, normalization metadata, final models and an external data-cache snapshot. It still lacks the information needed to exactly regenerate Table 3's eight-seed result.

### Cited findings
- Base is `GSAI-ML/LLaDA-8B-Instruct`, revision `08b83a6feb34df1a6011b80c3c00c7563e963b07`. README advertises only the four final DA+SFT+RL task-specific checkpoints in original `.pt` and derived HF export formats, not the natural-boundary or stage-only Table 3 checkpoints. [README lines 134–162](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/README.md#L134-L162).
- Released tree contains raw arrays for all four tasks, morphology relabels, all four task bundles, eight training plus two validation templates per task, normalization metadata and RL reward statistics. Training does not need Design-Bench initialization. [Data README lines 10–34, 64–81](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/data/README.md#L10-L34).
- The separate HF `DiBO-DesignBench-Snapshot` archive is advertised as the exact cache used in experiments; needed for TFBind8/Ant/DKitty oracle evaluation, including fixed morphology controller policies. It does not replace the repository task bundles. [Data README lines 36–62](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/data/README.md#L36-L62).
- TFBind10 canonical bundle cannot be exactly rebuilt from corrected raw lookup because historical tie ordering and normalization source were not retained. [Bundle code lines 131–136](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/dataset/task_bundle.py#L131-L136).
- Code requires caller-supplied training/evaluation seeds and does not enumerate the historical paper's eight seed values. Evaluation default transforms each seed to its square, samples random prompts by default, requires 128 *unique valid* candidates with a maximum 1000 attempts, and summarizes normalized maxima with population std `ddof=0`. [Eval defaults lines 514–578](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/eval.py#L514-L578); [candidate acceptance lines 236–283](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/eval.py#L236-L283); [summary lines 486–507](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/eval.py#L486-L507).
- Discrete preset: 1024 DA steps at 2e-5 then 1024 SFT steps at 2e-5, batch one, accumulation 16. Continuous preset: 2048 DA steps at 1e-5 then 1024 SFT steps at 2e-5, batch one, accumulation eight. PagedAdamW8bit and gradient checkpointing default on; no LoRA adapter code in the inspected training path. [Pipeline presets lines 28–41](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/src/pipeline.py#L28-L41); [train configuration](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/configs/train.yaml#L27-L49).

Commands below are a static recipe for a **new** reproduction, not executed and not a claim of exact historical seeds. In the audited checkout, repeat for each caller-selected training seed and boundary mode:

```bash
python main.py --use TFBind8-Exact-v0 --stages da sft \
  --seed <TRAIN_SEED> --special_token_type natural \
  --checkpoint_policy each_stage --extra_name tf8_natural \
  --da_lr 2e-5 --sft_lr 2e-5 --da_steps 1024 --sft_steps 1024 \
  --batch_size 1 --grad_accum_steps 16 --gradient_checkpointing \
  --warmup_steps 100 --lr_schedule warmup_constant \
  --output_dir outputs/tf8-natural --wandb_mode offline
# Repeat with special_token_type special and distinct output directory.
python eval.py --tasks TFBind8-Exact-v0 \
  --checkpoint_path <SFT_STAGE_CHECKPOINT> --seeds <EVAL_SEEDS> \
  --special_token_type natural --num_candidates 128 --max_attempts 1000 \
  --save_details --output_json outputs/tf8-natural-eval.json
# Match evaluation rendering to the corresponding arm.
```

This uses main's valid flags and pipeline-selected step presets. `scripts/run_pipeline.sh` hard-codes all three stages, so it must not be used unchanged under the no-RL constraint. [Main parser](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/main.py#L15-L85); [shell wrapper lines 33–52](https://github.com/zpointS/DiBO/blob/601fef5d502d0088a32841a477cb221beff105ef/scripts/run_pipeline.sh#L33-L52).

### Inferences
- Current evaluation's supplied seed list gives stochastic prompt contexts, not necessarily independent retrained models. A budget/report must distinguish eight evaluation seeds of one trained model from eight independently trained models per arm. Without historical manifests that distinction cannot be recovered from a mean/std table alone.

### Gaps
- Repository tree inspection found no pretraining-overlap ranking-probe implementation for Appendix A.7, original per-seed Table 3 outputs, original seed list, mapping from training seeds to evaluation seeds, ablation/stage checkpoints, or historical GPU timing logs. Claims of absence are scoped to this pinned repository and README-advertised artifacts, not the authors' private files or every external HF revision.
- Full dependency list and cost arithmetic are delegated to the cost notes; no commands above were run. No model files or dataset-cache ZIP were downloaded for this audit.
