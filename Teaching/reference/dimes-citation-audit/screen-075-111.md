# DIMES citer screening: S075–S111

Screened 2026-09-08. Citation eligibility comes from the saved Semantic Scholar direct-citer corpus; counts are not quality grades. Abstract means author abstract as returned by the index, with the linked primary source available; methods/results inspected denotes targeted primary full-text reading, not a complete replication.

## S075 — SymmetricDiffusers: Learning Discrete Diffusion on Finite Symmetric Groups

**DEFER** · 7 citations · evidence: methods inspected

Learns distributions over permutations of a fixed item set using riffle shuffles. The team generator chooses categorical contents, not just their order; slot-order invariance is already a planned diagnostic. [Primary source](https://arxiv.org/abs/2410.02942).

## S076 — Enhancing GNNs Performance on Combinatorial Optimization by Recurrent Feature Update

**SKIP** · 7 citations · evidence: abstract

Recurrent GNN features optimize an explicit differentiable QUBO loss; no such battle-strength objective is available and QUBO is parked. [Primary source](https://arxiv.org/abs/2407.16468).

## S077 — RouteExplainer: An Explanation Framework for Vehicle Routing Problem

**SKIP** · 7 citations · evidence: abstract

Explains route edges through counterfactual route costs and a route-intention classifier; does not validate a team-strength surrogate or team-edit effect. [Primary source](https://arxiv.org/abs/2403.03585).

## S078 — A Hierarchical Destroy and Repair Approach for Solving Very Large-Scale Travelling Salesman Problem

**SKIP** · 7 citations · evidence: abstract

Hierarchical compression of retained tour edges targets millions of cities. There is no equivalent safe compression of six interacting Pokemon sets. [Primary source](https://arxiv.org/abs/2308.04639).

## S079 — ML4CO-Bench-101: Benchmark Machine Learning for Classic Combinatorial Problems on Graphs

**DEFER** · 7 citations · evidence: primary repository

Useful benchmark code for classic graph problems, but not a team-generation evaluation method. Existing Unify ML4TSP covers the live learned-versus-search attribution question. [Primary source](https://github.com/Thinklab-SJTU/ML4CO-Bench-101).

## S104 concrete conditional reading

Read Sections 3.2–3.3 and 4.1–4.2. Test random versus confidence-weighted removal at the same expected number of replaced sets, crossed with greedy versus stochastic completion. Hold the existing checkpoint, starting teams and battle budgets fixed for a first project test, while explicitly noting the paper retrains each operator pairing. Preserve legality checks, unique-team frequencies and fresh battle evaluations. Confidence is likelihood of the generated field, not an estimate of its battle contribution; do not call low confidence a weak Pokemon. This is a conditional experiment, not a recommendation to replace the generator with ConsFormer.
