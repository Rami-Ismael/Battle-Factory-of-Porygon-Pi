## Scope and reproducibility

This is a source inspection, not an experiment. No training, sampling, or battles were run. The seven complete PDFs, including appendices and sample galleries, were downloaded and converted with `pdftotext -layout`. I searched for change, revision, edit, flip, settling, convergence, transition counts, and related terms, and inspected the relevant definitions, experimental sections, figures/captions, algorithms, and sampler implementations. Negative findings mean no matching definition/result was located in this reviewed material, not a proof that no such metric exists elsewhere.

PDF versions are pinned in the references: Schiff v3, Austin v3, Lou v3, Duo v3, GIDD v2, ReMDM v4, and Informed Correctors v5. These include revisions later than the first-submission years in the question. Code references pin the inspected default-branch commits, rather than assuming today's code is identical to the paper's original release. Python files were read through the GitHub contents API with a pinned `ref`, decoding `.content` from base64. No blogs or summaries were used.

## What Schiff's sampler actually records

The sampling loop initializes from the prior and repeatedly produces `xs` from `xt`. Its progress display reports the number of function evaluations, a probability-normalization check, and a not-a-number check. The comparison `torch.allclose(xs, xt)` decides whether to discard cached predictions. The loop then replaces `xt` and returns only the final sequence. There is no per-position history, first-setting timestamp, accumulated change count, or last-change timestamp in this loop. ([S-code](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1115-L1209); [S-cache](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1200-L1209))

For absorbing-state diffusion, `_ddpm_denoise` explicitly copies tokens whose input is not `[MASK]`; uniform diffusion instead samples the posterior without that copy restriction. The classifier-free guided version repeats this distinction. The paper explains the irreversible masked posterior in §2.1 and motivates uniform noise's editable outputs in §4 and the conclusion. This establishes the mechanism, without measuring its frequency. ([S](https://arxiv.org/pdf/2412.10193v3), §2.1 p. 3, §4 p. 5, conclusion p. 10; [S-denoise](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1211-L1253); [S-guided](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1255-L1340))

The classifier-based code also constructs candidate sequences differing at one position to evaluate guidance. Those candidate transitions are enumerated alternatives, not a log of edits actually taken by the sampler. [S-candidates](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1383-L1418)

## What the other sources establish

### Denoising diffusion with structured transitions

Austin's experiments evaluate likelihood, generation quality, and sample time; the appendices include uniform-noise generation snapshots. The text sampler optionally returns intermediate states with `return_intermediates`, while its output scalars describe steps and sequence length. Neither intermediate-state retention nor a displayed trajectory defines a revision count. The image sampler similarly returns the final sample, optionally with the initial sample. ([A](https://arxiv.org/pdf/2107.03006v3), §5 Tables 1–3, App. B.3 Figs. 12–13; [A-text](https://github.com/google-research/google-research/blob/03ac4dca9776084a3a002d4513a55dc7348f680e/d3pm/text/diffusion.py#L3153-L3285); [A-code](https://github.com/google-research/google-research/blob/03ac4dca9776084a3a002d4513a55dc7348f680e/d3pm/images/diffusion_categorical.py#L471-L538))

**Inference:** These intermediate states could support a newly specified adjacent-state change count, but the source does not supply the requested commitment convention or published count statistics. [A-text](https://github.com/google-research/google-research/blob/03ac4dca9776084a3a002d4513a55dc7348f680e/d3pm/text/diffusion.py#L3153-L3285)

### Score entropy sampling

SEDD's approximately `t*d` statement concerns the log-linear noise schedule. Its sampler draws from the limiting distribution, applies the configured predictor at each timestep, optionally performs final denoising, and returns the sample. It does not accumulate changes or define the first token setting. Thus the forward-noise statement must not be presented as a reported number of self-corrections. ([L](https://arxiv.org/pdf/2310.16834v3), §5.1 p. 5, App. C.1 p. 15; [L-code](https://github.com/louaaron/Score-Entropy-Discrete-Diffusion/blob/0605786da5ccb5747545e26d66fdf477187598b6/sampling.py#L59-L148))

### Uniform diffusion and deterministic distillation

Duo explicitly contrasts repeated updates in uniform-state diffusion with irreversible unmasking. Figure 5 is a schematic illustration, not an empirical distribution of edit counts. Appendix A.7 also describes the deterministic trajectory used to construct distillation targets: fixed clean data and fixed Gaussian noise yield a token that switches between its initial value and its clean value at most once. The appendix cautions against identifying that target construction with carry-over sampling by the trained Duo model. Its ordinary generation loop retains the current sample and prediction cache, without revision or settling counters. ([U](https://arxiv.org/pdf/2506.10892v3), Fig. 5 and App. [A](https://arxiv.org/pdf/2107.03006v3).7 pp. 22–23; [U-code](https://github.com/s-sahoo/duo/blob/7c9b498f5b717de064d6fad7e2509c866e6cb620/trainer_base.py#L743-L797))

### GIDD's count and its limits

GIDD applies correction to generated samples. It proposes repeated single-token replacement, and reports up to 10% changed tokens in Fig. 3(a). Section 5.4 reports generative perplexity improving from 214 to 93.3 and self-accuracy from 62.0% to 73.5% for its larger model trained with 20% uniform noise. These are quality/agreement results, not counts of repeated edits. ([G](https://arxiv.org/pdf/2503.04482v2), §3.4 p. 5, §5.4 p. 8, Fig. 3 p. 7)

The official implementation makes the count precise:

```python
z_t_init = z_t.clone()
# correction loop updates z_t
num_changes = (z_t_init != z_t).sum().item()
```

It processes one saved sequence at a time, stores `num_changes` as a metric, and writes the metrics to a comma-separated values file. Thus its count is endpoint Hamming distance over token IDs, not cumulative transition events. A changed position contributes one even if edited repeatedly; a return to the starting token contributes zero. Generation's initial noise and first denoising assignment are excluded because the saved reference is the input to correction. ([G-count](https://github.com/dvruette/gidd/blob/f67acc961cc858cc69e8e6d91e7eb67a0a79151c/gidd/eval/self_correction.py#L42-L99), lines 42–54, 62–96)

Each correction step samples proposals, scores proposals that differ from the current token, and selects the configured number of positions. The code computes self-accuracy as agreement between the proposed updated sequence and the current forward pass's maximum-logit token IDs. It stops on unchanged sequence or patience exhaustion, subject to a step budget. This is a sequence-level stopping procedure, not an irreversible token commitment. ([G-step](https://github.com/dvruette/gidd/blob/f67acc961cc858cc69e8e6d91e7eb67a0a79151c/gidd/eval/self_correction.py#L11-L24); [G-count](https://github.com/dvruette/gidd/blob/f67acc961cc858cc69e8e6d91e7eb67a0a79151c/gidd/eval/self_correction.py#L42-L99), lines 56–78)

Appendix C acknowledges oscillation and gives early-stopping patience 32. **Inference:** A temporary unchanged token, or high self-accuracy, therefore should not be treated as an established per-token commitment event. ([G](https://arxiv.org/pdf/2503.04482v2), App. C pp. 15–16; [G-count](https://github.com/dvruette/gidd/blob/f67acc961cc858cc69e8e6d91e7eb67a0a79151c/gidd/eval/self_correction.py#L42-L99))

### Remasking and informed correction

ReMDM specifies a remasking backward process and controllable remasking schedules. Its implementation recognizes unmask/remask events to update confidence scores, and uses batch equality to control caching, but does not aggregate those events into a revision metric. No published count in the inspected experiments distinguishes first unmasking, repeated unmasking with the same lexical token, and replacement by a different lexical token. ([W](https://arxiv.org/pdf/2503.00307v4), §§3–4, App. C Algorithms 2–3; [W-confidence](https://github.com/kuleshov-group/remdm/blob/f830d659fb98d9b2c79ff71bfa12d578312b688a/diffusion.py#L740-L788); [W-code](https://github.com/kuleshov-group/remdm/blob/f830d659fb98d9b2c79ff71bfa12d578312b688a/diffusion.py#L847-L893))

Informed Correctors targets non-mask token positions using model-based scores. Its implementation selects low-score positions for categorical resampling, without requiring the sampled value to differ. Its synthetic error count measures impossible transitions between adjacent positions within the final sequence; its text error rate concerns characters in out-of-vocabulary words. Neither measures transitions across sampling time. ([Z](https://arxiv.org/pdf/2407.21243v5), §3.1 pp. 5–6, §5.1 Eq. 17 p. 8, §5.2 p. 8; [Z-code](https://github.com/lindermanlab/informed-correctors/blob/8371dec19404eae279a4eb5ea4e06977d8d173b6/text8/md4/models/diffusion/hollow_md4.py#L332-L383))

**Inference:** Remasking probabilities, selected correction positions, corrector steps, and actual token-ID changes cannot be substituted for one another. In particular, a resampling operation need not change a token, and a remask/unmask cycle can restore the same token. ([W-confidence](https://github.com/kuleshov-group/remdm/blob/f830d659fb98d9b2c79ff71bfa12d578312b688a/diffusion.py#L740-L788); [Z-code](https://github.com/lindermanlab/informed-correctors/blob/8371dec19404eae279a4eb5ea4e06977d8d173b6/text8/md4/models/diffusion/hollow_md4.py#L332-L383))

## Answer about commitment, and a possible project convention

**Inference:** There is no usual uniform-noise commitment or settlement definition established by this source set. The directly relevant empirical precedent is GIDD's post-generation endpoint distance, which answers a different question. None of the checked sources defines the first departure from a random initial value as a token's first commitment. ([S](https://arxiv.org/pdf/2412.10193v3)–[Z](https://arxiv.org/pdf/2407.21243v5); sampler references above)

The following are proposed operational definitions, **Inference**, not literature standards or implemented measurements. Let `x[0]` be the actual prior sample, and `x[1], ..., x[K]` the retained sampler states in generation order. Include any final cleanup/argmax step as a separately identified transition.

- Count all observed token changes with `C_i = sum(k=1..K) 1[x[k,i] != x[k-1,i]]`. The first change away from random initialization counts. Resampling the same ID does not.
- If the project wants a first-departure convention, define `F_i = min{k >= 1: x[k,i] != x[0,i]}` and count subsequent changes only: `R_i = max(C_i - 1, 0)`. The first departure is excluded, including when it occurs after several unchanged steps. Call this “changes after first departure,” without claiming the token was semantically committed.
- Retrospective settlement can mean `S_i = min{k in 0..K: x[j,i] == x[K,i] for every j >= k}`. This includes `S_i = 0` for a token that never changes. It is the last-change index, not the first visit to the final value. Settlement is known only after the trajectory ends; changes after settlement are zero by definition.

**Inference:** For the ordinary absorbing sampler, first departure from `[MASK]` coincides with its irreversible setting and `R_i = 0`. For uniform noise, first departure may simply be an early noise-to-noise edit, so `R_i` measures editing activity under this convention, not successful error correction. Report it alongside total changes, endpoint distance, timestep mesh, and final-cleanup policy. A discrete sampler trace counts changes between recorded states, not any unobserved continuous-time jumps inside a step. ([S-prior](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L855-L862); [S-denoise](https://github.com/kuleshov-group/discrete-diffusion-guidance/blob/edb0f8c28b7caeb4ea7a06a2fee8d74ab6da1661/diffusion.py#L1211-L1253); [L](https://arxiv.org/pdf/2310.16834v3), §4.1, pp. 4–5)
