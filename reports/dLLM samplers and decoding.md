# dLLM samplers and decoding

A sampler is the procedure that repeatedly asks a model for predictions and decides which tokens to write into an unfinished sequence. The project's decoder acts afterward: it turns token IDs into text, parses a team, fills missing spreads under the existing policy, and checks the resulting Showdown paste. At pinned dLLM commit `ca176752fbceec49c6b4777a2c18ae88e4eb10ed`, the source contains **eight concrete inference sampler classes**, plus a distinct original random-reveal algorithm in Dream's model-generation method. Sampler modes and duplicate entry points should not be counted as extra model families. Some fill masks permanently; LLaDA2.1 can replace filled tokens; EditFlow can also insert and delete tokens. None supplies Pokémon legality rules. No source inspection can establish which produces the most legal, diverse teams per second on the M4 Pro.

## The sampler creates tokens before the decoder checks a team

A token is a vocabulary ID, often representing a word fragment. A mask token marks an unknown position. The model is the learned network that produces scores, called logits, over possible tokens. A forward pass is one evaluation of that network. The sampler uses those scores to propose token identities, choose positions to commit, and decide when to ask again. A schedule controls how many positions to fill or how update rates change over time. Confidence here is a model probability or another score derived from its distribution. It is **not a probability that Showdown accepts the team**. [The masked sampler's update loop][u-mdlm-loop] and [the local threshold calculation][p-port] show these operations directly.

A fully bidirectional masked model can consult visible tokens on both sides of a hole. A block model restricts a token to earlier blocks and its own block. A sampler having a `block_size` setting does not itself make its model block-trained: the generic masked sampler still calls its model on the full sequence, whereas the block sampler constructs block-causal attention and repeatedly computes only the current block with cached earlier state. A key/value cache stores intermediate attention results to avoid recalculating them. [Masked full-canvas calls][u-mdlm-canvas]; [block attention][u-bd-attn]; [block calls][u-bd-loop].

The project already separates generation from `tok.decode(..., skip_special_tokens=True)`. Its later `decode()` parses six slots, requires species/ability/moves, assigns missing Stat Point spreads using a same-species corpus entry or random legal spread, serializes Showdown text, and rejects validator failures. Acceptance therefore measures the sampler together with this downstream policy. A transformer's internal "decoder layer" is a different architectural term. Papers also use "decoding" for the entire generation procedure; this report uses the ticket's narrower output-conversion meaning. [Generation and token decoding][p-decode]; [team decoder][p-team]; [internal decoder-layer terminology][p-layers].

The existing block implementation in `code/src/textdiff_port.py` greedily predicts the next block's first token, then fills masks within sub-blocks using token proposals and confidence-threshold selection, always forcing at least one position. The inspected settings are block size 32, sub-block size 8, threshold .9, token temperature 1, and top-p 1. Temperature changes token proposals; a position-selection rule changes which proposals are committed. Those are separate choices, although temperature can also change the confidence scores used for position selection. Local guidance combines scores as `g*conditional + (1-g)*unconditional`; upstream generic masked guidance uses `(1+s)*conditional - s*unconditional`. Matching numeric knob values would therefore compare different strengths. [Local implementation][p-port]; [upstream guidance][u-mdlm-guidance].

## Eight classes cover filling, cache reuse and editing

The inventory below comes from source, not README claims. Core exports contain two classes; ordinary LLaDA and BERT evaluation use the generic masked class. The exact requested directory `dllm/pipelines/fastdllm/llada` exists and contains `__init__.py`, `eval.py`, `sampler.py`, `models/__init__.py`, `models/configuration_llada.py`, and `models/modeling_llada.py`. Its package exports the Fast LLaDA sampler and registers its cache-aware masked model. [Core exports][u-core]; [ordinary LLaDA wiring][u-llada-eval]; [BERT wiring][u-bert-eval]; [Fast LLaDA directory][u-fast-dir]; [Fast LLaDA exports][u-fast-exports].

Token temperature controls how strongly proposals favor high-scoring vocabulary items. Top-k filtering keeps only the k most probable vocabulary items; top-p filtering keeps a set reaching the chosen probability mass. Position temperature, called `alg_temp` in Dream, separately randomizes which holes to fill. A top-two margin measures the gap between the best and second-best token probabilities. Entropy measures how spread out a distribution is, so negative entropy favors concentrated predictions. Classifier-free guidance compares scores with the prompt visible and hidden to strengthen conditioning. EOS means end-of-sequence. EditFlow's `tau` is the size of one time increment. These settings operate on model predictions, not legal-team choices.

The LLaDA2 and LLaDA2.1 model files also embed `generate()` implementations of their respective families. They are alternate entry points, not two further sampler families; their defaults and output/end-of-sequence handling differ from standalone wrappers. Embedded generation defaults to 2048 tokens versus 128 in the wrappers. `BaseSampler` is abstract plumbing. EditFlow's `X0Sampler`, `SampleX0Empty` and `SampleX0Masks` generate training starting states, not model-guided inference sequences. [Embedded LLaDA2 generation][u-llada2-embedded]; [embedded LLaDA2.1 generation][u-llada21-embedded]; [abstract base][u-base]; [training starting states][u-x0].

The word `remasking` is particularly misleading in ordinary masked, block and Fast LLaDA loops. These implementations only change positions still containing MASK. They do not erase committed tokens and try again. True revision is present in LLaDA2.1 and EditFlow; it is not implied by a confidence-ranking option's name. Schedulers and cache choices are also modes or helpers, not additional inference classes. The shared count scheduler removes zero-transfer steps and supports deterministic rounding or stochastic counts, so a configured `steps=128` does not necessarily mean 128 forward calls. [Masked commit condition][u-mdlm-loop]; [Fast selection][u-fastllada-select]; [transfer schedule][u-transfer].

## Legality and diversity require downstream measurements

The following is engineering judgement, not an observed outcome. Filling fewer positions at once can let later predictions react to earlier commitments, but costs more model evaluations. Greedy tokens and strict vocabulary filtering can concentrate outputs; randomized token or position selection can widen them. Confidence order can commit easy fields before difficult ones, but neither that score nor a .99 threshold checks species/move compatibility. Editing can repair an inconsistency or introduce one; insertion and deletion can repair paste structure or break it. Cache reuse changes what context is recomputed and can change predictions. These are reasons to measure, not evidence of a winner.

For this project, cost per accepted team is total generation, text conversion, parsing, spread completion and validation time divided by accepted team count. Unique accepted teams per second additionally depends on duplicate rate and the chosen diversity definition; six-species novelty needs its named reference set. A sampler with fewer passes can lose if its acceptance rate is worse. Raw tokens per second, step count, and image-diversity results therefore cannot decide the VGC objective. The historical results in `code/docs/textdiff.md` concern the existing block checkpoint and its settings; the document explicitly measures legality by parsing and Showdown rejection. They are not estimates for the upstream inventory. [Project baseline and validity policy][p-textdiff].

No seconds/team, memory budget or useful-throughput ranking was measured. The strongest applicability distinction supported here is that compatible mask-filling loops are candidates for masked models, while block-attention recipes, cache APIs, token-edit training and EditFlow's extra output heads impose additional requirements. A pretrained model originally described as "decoder-only" can be adapted to different attention during training; the name alone does not select a valid sampler or validate its output.

Mask proposals are not universally prevented from proposing MASK again. LLaDA2/LLaDA2.1 standalone wrappers round output length to blocks without final truncation, and the LLaDA2 EOS option breaks the inner loop rather than the whole method. These are source observations, not reproduced runtime bugs.
