# Checkpoint files narrow the masked candidates

All seven requested names resolve to real checkpoints, and the inspected inference implementations use fully bidirectional attention. **The two small masked Qwen checkpoints are the strongest candidates for further laptop investigation**, because their configured position limits admit a 24,644-token prompt and they have matching block-diffusion siblings. That does not establish that the released samplers fit beside battles. DiffuGPT small and medium, DiffuLLaMA, and LLaDA exclude that prompt by their configured position limits. Dream admits it by configuration, but its unchanged BF16 sampler exceeds the laptop's memory from weights and overlapping logits alone under the allocation assumptions below. Short prompts retain more candidates, with the small GPT checkpoints particularly light. None has been run or benchmarked in this research.

This report answers [issue 162](https://github.com/Rami-Ismael/Battle-Factory-of-Porygon-Pi/issues/162) for the M4 Pro with 24 GB unified memory, using the scope in [parent map 160](https://github.com/Rami-Ismael/Battle-Factory-of-Porygon-Pi/issues/160). Inspection date is 2026-11-05. Earlier project notes, `code/docs/textdiff.md` and `code/docs/textdiff-speed-research.md`, supplied leads; checkpoint files and pinned implementation code control the findings here. “Dream” means Dream-v0-Base-7B and “LLaDA” means LLaDA-8B-Base. LLaDA Instruct was checked separately and has the same dimensions, size, dtype, context limit and mask ID; that does not establish equal behavior.

## Source code establishes full attention and repeated prompt cost

For the GPT/Llama family, the diffusion wrapper fills GPT causal biases with true values and constructs an all-zero additive mask at inference. The Llama patch passes that mask through, with a noncausal FlashAttention alternative. Stock causal-model loading is therefore insufficient even though the checkpoint dimensions look familiar. The same code sends the complete noisy canvas through the model at each denoising step; a source mask protects the prefix from replacement, not computation. These are static findings from HKUNLP/DiffuLLaMA revision `c17e897f6476c174b4623da594e4c65554f1613d`. ([Wrapper/sampler](https://github.com/HKUNLP/DiffuLLaMA/blob/c17e897f6476c174b4623da594e4c65554f1613d/model.py), [attention patch](https://github.com/HKUNLP/DiffuLLaMA/blob/c17e897f6476c174b4623da594e4c65554f1613d/attention_patch.py))

Dream's SDPA explicitly uses noncausal attention; its full-attention sampler constructs no block mask. LLaDA does the same and expressly asserts against key/value caching. The LLaDA sampler's `block_length` controls which output positions can be committed during each phase. It does not prevent tokens from attending across those regions. Its `block_type=llama` config value identifies a transformer module, not a block-causal attention pattern. ([Dream model](https://huggingface.co/Dream-org/Dream-v0-Base-7B/blob/6572adb5535263e4d1a337b56942ba48b6dee2a9/modeling_dream.py), [LLaDA model](https://huggingface.co/GSAI-ML/LLaDA-8B-Base/blob/0f2787f2d87eac5eed8a087d5ecd24277e6255b2/modeling_llada.py), [LLaDA sampler, revision `9182493720ed723ef8031210d85959364e51cbe0`](https://github.com/ML-GSAI/LLaDA/blob/9182493720ed723ef8031210d85959364e51cbe0/generate.py))

Both masked Qwen implementations replace causal mask construction with a padding-only 4D mask. Their default layer configuration is full attention with no sliding window. A caller can still supply another mask; the claim is about the released default forward. The MDLM sampler likewise calls the model on the whole canvas without reusable `past_key_values`. Its optional reveal-window schedule does not establish block attention. ([Coder model](https://huggingface.co/dllm-hub/Qwen2.5-Coder-0.5B-Instruct-diffusion-mdlm-v0.1/blob/a284e895a6248256baf2f60502e54aba61b24c1a/modeling_qwen2.py), [Qwen3 model](https://huggingface.co/dllm-hub/Qwen3-0.6B-diffusion-mdlm-v0.1/blob/c8d24a3f4adaeef46881b450e1bf7d1005203bd7/modeling_qwen3.py), [MDLM sampler, revision `ca176752fbceec49c6b4777a2c18ae88e4eb10ed`](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/mdlm.py))

Consequently, **all inspected samplers recompute prompt tokens every denoising step**. Standard autoregressive prefix KV caching is not exact here: deeper prompt representations depend on the changing generated region through bidirectional attention. Static token IDs, masks, embedding lookups and position frequencies can be retained in a custom implementation. That does not remove the prompt's transformer passes. Approximate cross-step caches need separate accuracy checks. Dense attention arithmetic grows with the square of prompt-plus-output length per step; projections, feed-forward layers and vocabulary scoring grow linearly. This is an inference from the inspected computations, not a timing result.

## Small weights do not settle long-prompt memory

The earlier “Qwen3 0.8B with embeddings” note needs qualification. The header stores two 155,582,464-element token matrices, giving **751,632,384 serialized scalars**. The config requests tied embeddings, and the model inherits Transformers tying machinery; the corresponding unique tied total is **596,049,920**. Removing the shared token matrix gives 440,467,456 transformer parameters. The coder checkpoint has the same discrepancy, 630,167,424 stored versus 494,032,768 config-implied unique parameters. Headers cannot establish whether the separately stored matrices have equal values. If they differ, tied loading can discard one trained matrix. Resolve the intended loading convention before a later benchmark. ([Transformers tying implementation, revision `8ac2b916b042b1f78b75c9eb941c0f5d2cdd8e10`](https://github.com/huggingface/transformers/blob/8ac2b916b042b1f78b75c9eb941c0f5d2cdd8e10/src/transformers/modeling_utils.py), model/config/header links in matrix)

Memory arithmetic assumes batch one, inference without gradients, no classifier-free guidance, native 16-bit weights and total sequence length S. It excludes loading duplication, allocator overhead, OS and battle memory. The GPT/Llama planning scenario is weight payload plus twice one FP32 attention-score tensor, six FP32 full-logits tensors and 1 GiB workspace. Its multipliers are planning assumptions, not verified live allocations. With a hypothetical 4 GiB OS/battle reserve, the totals become 6.48, 6.94 and 24.48 GiB respectively. Thus small GPT checkpoints retain substantial apparent room at native context; DiffuLLaMA at 4,096 is excluded under that scenario, not under every possible implementation. Its released initial forward also lies outside the later loop's `no_grad` block, so an inference-mode port would need to address graph retention. ([GPT/Llama sampler](https://github.com/HKUNLP/DiffuLLaMA/blob/c17e897f6476c174b4623da594e4c65554f1613d/model.py))

Dream gives a stronger conditional exclusion. At S=24,644, `2*S*152064` bytes is 6.980 GiB of BF16 logits. Its sampler creates another full-size shifted logits tensor with `torch.cat` while the original remains live. With 14.185 GiB weights, that is **28.146 GiB before other allocations**. This rules out native BF16 weights plus that unchanged sampler at the long prompt, even if attention is efficient. It does not rule out a modified output-only projection, quantization, or short prompts. Those alternatives were not verified. LLaDA at 4,096 has a 15.895 GiB weights-plus-logits component sum; its actual peak remains unknown. ([Dream sampler](https://huggingface.co/Dream-org/Dream-v0-Base-7B/blob/6572adb5535263e4d1a337b56942ba48b6dee2a9/generation_utils.py), [LLaDA sampler](https://github.com/ML-GSAI/LLaDA/blob/9182493720ed723ef8031210d85959364e51cbe0/generate.py))

For either small Qwen at S=24,644, one BF16 full-vocabulary logits tensor costs 6.974 GiB. Retaining logits and probabilities costs 13.949 GiB; adding tied weights and a BF16 expanded square padding mask gives the matrix's 16.000/16.190 GiB component sums. These are not credible exact peak predictions. FP32 logits plus probabilities alone reach 27.897 GiB. Eager attention's FP32 softmax matrix alone reaches 31.675/36.199 GiB, so that long-context path is excluded. Efficient SDPA exists in code, but no MPS allocation pattern was measured. Computing output-position logits only and retaining fewer vocabulary-sized buffers are possible implementation changes, not released verified properties. At S=2,048, BF16 logits plus probabilities fall to approximately 1.159 GiB, illustrating why short-prompt candidates remain open. ([Inherited Qwen3 attention/head](https://github.com/huggingface/transformers/blob/8ac2b916b042b1f78b75c9eb941c0f5d2cdd8e10/src/transformers/models/qwen3/modeling_qwen3.py), [mask expansion](https://github.com/huggingface/transformers/blob/8ac2b916b042b1f78b75c9eb941c0f5d2cdd8e10/src/transformers/modeling_attn_mask_utils.py))

No candidate is verified to run unchanged on this laptop. Generic eager/SDPA paths avoid a mandatory CUDA-only attention kernel, but CUDA device choices and sampler float64 operations still require inspection or changes for MPS. The Qwen helper uses float64 token-transfer counts; LLaDA uses float64 noise/logits at nonzero sampling temperature. BF16 support, backend dispatch and actual battle headroom remain runtime questions. ([Qwen sampler helper](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/dllm/core/samplers/utils.py), [LLaDA sampler](https://github.com/ML-GSAI/LLaDA/blob/9182493720ed723ef8031210d85959364e51cbe0/generate.py))

## Licensing and swap controls need precise boundaries

Apache-2.0 section 4 requires distributing the license, preserving applicable notices, marking modified files and carrying applicable NOTICE attribution. A public fine-tune should also record exact parent checkpoint/revision and weight/tokenizer/code changes for provenance, although that recommendation exceeds the literal license minimum. Dream has an actual Apache upstream code license, and both Qwen upstream bases and dLLM code do too. Their adapted checkpoints' license declarations remain metadata-level evidence rather than standalone weight-license documents. ([Dream license, revision `31f94a60d187e3fd481fee3bbc2c732eb94a879c`](https://github.com/DreamLM/Dream/blob/31f94a60d187e3fd481fee3bbc2c732eb94a879c/LICENSE), [Qwen coder license, revision `ea3f2471cf1b1f0db85067f1ef93848e38e88c25`](https://huggingface.co/Qwen/Qwen2.5-Coder-0.5B-Instruct/blob/ea3f2471cf1b1f0db85067f1ef93848e38e88c25/LICENSE), [Qwen3 license, revision `c1899de289a04d12100db370d81485cdf75e47ca`](https://huggingface.co/Qwen/Qwen3-0.6B/blob/c1899de289a04d12100db370d81485cdf75e47ca/LICENSE), [dLLM license](https://github.com/ZHZisZZ/dllm/blob/ca176752fbceec49c6b4777a2c18ae88e4eb10ed/LICENSE))

GPT-2's Modified MIT license requires its copyright and permission notice. DiffuLLaMA's Apache metadata does not resolve the claimed Llama 2 derivative's license obligations. The Llama 2 agreement requires the agreement with derivative distributions, its attribution in a Notice file, compliance with the incorporated acceptable-use policy, and restricts using its materials/results to improve other LLMs outside Llama 2 derivatives; it also contains the 700-million-monthly-active-user permission condition. The weight lineage is author-asserted, not proved by shapes. LLaDA declares MIT in checkpoint and upstream READMEs, but a complete model copyright/permission notice was not found; a third-party license is not a substitute. ([GPT-2 license, revision `9b63575ef42771a015060c964af2c3da4cf7c8ab`](https://github.com/openai/gpt-2/blob/9b63575ef42771a015060c964af2c3da4cf7c8ab/LICENSE), [Llama 2 license, revision `7565eb6fee2175b2d4fe2cfb45067a61b35d7f5e`](https://github.com/meta-llama/llama/blob/7565eb6fee2175b2d4fe2cfb45067a61b35d7f5e/LICENSE), [LLaDA declaration](https://github.com/ML-GSAI/LLaDA/blob/9182493720ed723ef8031210d85959364e51cbe0/README.md#license))

The two Qwen block siblings are the closest verified swap controls: their configs and tokenizer settings match their masked partners. That supports an architectural comparison, not a claim of equal pretraining data, steps or compute.
