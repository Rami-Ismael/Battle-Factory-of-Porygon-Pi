Max coverage vs set cover

Fix k and maximise covered weight — versus cover everything and minimise k.

Lesson 0001 · 2026-08-18 · ~10 minutes · reference sheet · mission · answers TODO item “11. max coverage vs set cover” in Todo Section.md

Why this, now. Your vault records one clarifying move so far: weighted set cover → weighted maximum coverage as the formulation of f. This lesson makes that move defensible in one breath: you should be able to say which problem f is, why the other one is the wrong shape, and what changes in the algorithm and its guarantee.

1. Both problems, in one sentence each

The cleanest primary-source statement is the opening of Feige’s 1998 paper — the paper that proved both greedy guarantees are essentially best possible:

“Given a collection 𝓕 of subsets of S = {1,…,n}, set cover is the problem of selecting as few as possible subsets from 𝓕 such that their union covers S, and max k-cover is the problem of selecting k subsets from 𝓕 such that their union has maximum cardinality. Both these problems are NP-hard.” 🟢 Feige, A Threshold of ln n for Approximating Set Cover, JACM 45(4), 1998 — abstract. “Max k-cover” is the same thing as maximum coverage.

Same ingredients — a universe of elements and a family of subsets — and the two problems are what you get by swapping which quantity is fixed and which is optimised:

what is fixedthe target: every element must be coveredthe budget: at most k sets
what is optimisedminimise the number (or total cost) of setsmaximise the number (or total weight) of covered elements

2. The mirror: constraint and objective trade places

Written as integer programs the swap is literal. Let xj = 1 if set Sj is chosen, and for max coverage ye = 1 if element e ends up covered.

s.t. ∑j : e ∈ Sj xj ≥ 1  for every element e
xj ∈ {0,1} 		max ∑e we ye
s.t. ∑j xj ≤ k
ye ≤ ∑j : e ∈ Sj xj  for every element e

Read the columns against each other. Set cover’s constraint (“every element gets ≥ 1”) becomes max coverage’s objective (“as much weight as possible gets ≥ 1”). Set cover’s objective (“few sets”) becomes max coverage’s constraint (“≤ k sets”). That is the whole relationship. (ILP for max coverage as on 🟢 Wikipedia — Maximum coverage problem; set cover LP as W&S §1.2.)

The trap: “weighted” is not one word

In weighted set cover the weights are costs on the sets (W&S: “a nonnegative weight wj ≥ 0 for each subset Sj… find a minimum-weight collection of subsets that covers all of E”). In weighted maximum coverage the weights are values on the elements. Your project’s weights — how often each meta team appears in the collected list — sit on elements. So “weighted set cover”, which your TODO ticks as understood, is a different weighting from the one f uses. If sets also carry costs and you replace k with a spend limit, that is the budgeted maximum coverage of Khuller, Moss & Naor (🔒 IPL 1999; abstract on Semantic Scholar) — still 1 − 1/e, still not set cover.

3. Try it: one instance, two readings

Seven meta teams, weighted by how many times each appears in the list (T′1 ×6, T′2 ×5, the rest ×1). Four candidates, letters not species — the “beats” pattern is invented for the exercise, so nothing here is a matchup claim. Budget k = 2 for the max-coverage reading (your real k is 6).

  1. Max coverage. Find the pair that covers the most weight. (There is one best pair; the panel confirms it.)
  2. Set cover. Reset, then find the fewest candidates that cover every column. There is exactly one minimum cover.
  3. Compare the two answers. The best pair is not a subset of the minimum cover — the two problems do not agree on which candidates matter. Set cover is forced to take A and B for the singleton columns; max coverage ignores those columns and takes C for the two heavy ones.
  4. Reset and press Greedy step four times. It reaches full cover using four candidates, one more than the minimum. That greedy chases weight, which is what maximum coverage wants and what set cover does not care about. On an unweighted instance the two greedies pick in the same order and differ only in when they stop; add element weights and even the order splits.

4. Which one is f

Map your objects onto the ingredients: universe = the collected meta-team list; element weight = frequency in that list; a set = the meta slice one candidate beats; and the number of candidates on a team is six, fixed by the rules. A fixed count you are not allowed to minimise is a budget k, and a budget is the signature of maximum coverage. So at the species layer, f in its coverage form reads: choose 6 slices whose union has the largest weight. Set cover would instead ask how many candidates does it take to beat every meta team? — a legitimate diagnostic (if the answer is 9, no team of six covers the meta and you are choosing what to concede), but not the objective, and it is infeasible outright whenever some meta team is beaten by no single candidate. Maximum coverage never becomes infeasible; it just reports a lower number.

Two things this lesson deliberately does not settle, because they are separate checkboxes: whether coverage is the definition of f or a proxy checked against the matchup predictor (item 9), and what to do about “beats” being binary when a matchup is a probability (item 8). On the second: W&S §2.5 solves exactly the soft version — choose k things, score each element by the best chosen value maxi∈S vij, still greedy, still 1 − 1/e — which is a strong candidate for the next lesson.

5. Retrieval check

Answer from memory before scrolling back. Every option has the same word count on purpose.

Which statement has the set-cover shape?

(a) fixes the target (everything) and minimises the count. (b) is maximum coverage. (c) has two objectives and no fixed quantity — ill-posed until you fix one. (d) fixes both — it is a yes/no feasibility question (“is there a 6-cover?”), not an optimisation.

In weighted set cover, the weights sit on…

Set costs (W&S §1.2). Element weights belong to weighted maximum coverage — the one your meta-team frequencies match.

On an unweighted instance, how do the two greedy algorithms differ?

Both add the set with the most uncovered elements; set cover stops at full coverage, max coverage after k picks. With costs or element weights the choice rule splits too (you saw it in the sandbox).

Greedy for maximum coverage guarantees…

1 − 1/e of OPT — of what the best k sets could cover, not of the whole universe (c is the classic misreading). (d) is set cover’s guarantee, and it bounds a count from above, not a value from below.

Why is f maximum coverage rather than set cover?

Six is a budget you cannot shrink or grow, so the only free quantity is how much weight the six cover. (b) is the set-cover target — and often unattainable; (c) is set cover’s objective; (d) is budgeted max coverage, a different variant.
