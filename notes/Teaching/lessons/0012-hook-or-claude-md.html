Who runs the rule?

A hook and CLAUDE.md look like two places to write instructions. They are run by two different things.

Your delegation goal: get Claude Code to consider a subagent on every real task without typing it. Your setup already uses both mechanisms for this. After this lesson you can say, for any rule, which mechanism should carry it.

Before reading on, predict: your CLAUDE.md says never tick a TODO checkbox. Can Claude still tick one?

Yes. CLAUDE.md is text the model reads. Nothing outside the model checks whether it was followed. The rest of the lesson explains why.

1. Ask one question: who runs it?

CLAUDE.md is read by the model. It is loaded into the context window at the start of a session, and Claude weighs it like any other text. The docs say so directly:

Claude treats them as context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead.🟢 Claude Code docs, “How Claude remembers your project”

A hook is run by the harness, the Claude Code program around the model. It is a shell command that fires at a fixed moment, whatever the model is thinking:

Claude Code runs them at specific points in its lifecycle, which gives you deterministic control: certain actions always happen rather than relying on the LLM to choose to run them.🟢 Claude Code docs, “Automate actions with hooks”

Your two real hooks. The prompt hook is subagent-nudge.mjs. The tool hook is require-writing-for-agents.mjs, which blocks edits to agent files until the writing-for-agents skill has run (added October 20). A third guard blocked the first save of this very lesson, because the path pointed outside this session's worktree.

2. Two kinds of hook: one asks, one enforces

A hook runs for certain, but what it can do depends on its event. A prompt hook (UserPromptSubmit) adds text beside your message. The model reads that text and can still ignore it, so it asks, just closer to the moment. A tool hook (PreToolUse) runs before a tool call and “can block it”. That is the one that enforces. 🟢 hooks guide, event table

The event table adds a detail you met in practice: the prompt hook “also fires on turns Claude Code starts on its own”. That's why your subagent note showed up on subagent reports and background notices.

Which mechanism can stop Claude from doing something it has decided to do?

Only a PreToolUse hook sits between Claude's decision and the action. A prompt hook note is more text for the model to weigh.

3. The sorting rule

  1. Does following it need judgement? Meaning, intent, “is this a task or a question”. Put it in CLAUDE.md. A shell script can't read meaning.*
  2. Must it hold even when Claude forgets or disagrees? Put it in a tool hook gate, on the tool call that would break it.
  3. Is it a reminder that should sit next to the newest prompt? Put it in a prompt hook note. It still only asks.

*The docs also offer prompt-based and agent-based hooks that ask a Claude model to judge a condition. Those trade the guarantee of a script for judgement.

Practice on your own rules

“Use candidate and team exactly as GLOSSARY.md defines them.”

Judgement. Whether a sentence uses “team” in the glossary's sense is a question of meaning, so no script can check it.

“Refuse any edit to a SKILL.md until the writing-for-agents skill has been called.”

This is your own PreToolUse hook. “Refuse” means enforce, and the check is mechanical: was the skill called earlier in the transcript?

“Put a one-line subagent reminder beside each prompt that looks like a task.”

A reminder at the moment of each prompt is exactly what UserPromptSubmit does. It's your subagent-nudge hook.

“Decide whether the prompt is a task or a question before writing the Subagent line.”

Judgement. Your hook's gate only counts words, which is why it fires on twelve-word questions. The criteria live in CLAUDE.md for that reason.

“Never write a ticked checkbox into Todo Sectoin.md, even if Claude forgets the rule.”

“Even if Claude forgets” calls for enforcement, and the check is mechanical: does the edit's new text contain “- [x]”? Today this rule lives only in CLAUDE.md. A gate has the same gap as your writing-for-agents gate: an edit made through Bash never reaches it.

“Start a Haiku subagent for every paper PDF longer than twenty pages.” Which mechanism can guarantee it?

No hook can make Claude start a subagent. A tool hook can only block a different action, such as reading the PDF directly, and then hope Claude delegates. That is why your subagent check is a request, not a guarantee.

4. Your takeaway

Your subagent setup is correct for what it is. Choosing a subagent needs judgement, so the criteria live in CLAUDE.md. The prompt hook keeps a short reminder next to each new prompt. There is no tool hook, because nothing can be blocked into existence.
