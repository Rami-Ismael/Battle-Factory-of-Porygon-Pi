## Notes

- **Why:** our 84-field model hides fields at a per-field masking rate and decodes in a fixed order, unlike the papers. The owner suspects these departures cause decoding errors and wants the work to "closely resemble other people work" (2026-11-11).
- **Yardsticks (owner, 2026-11-11):** MD4 for training and masking rates (Shi et al., "Simplified and Generalized Masked Diffusion for Discrete Data", NeurIPS 2024, https://arxiv.org/abs/2406.04329); LLaDA for decoding (Nie et al., "Large Language Diffusion Models", NeurIPS 2025, https://arxiv.org/abs/2502.09992). Cite every design choice to a section, equation or algorithm, or mark it as our own.

- **The four rows** (one training seed for each new model; 3 sampling seeds at each of guidance 2, 4 and 8):

  | Masking rate in training | Decoding order | t given to the model while decoding | Source |
  | --- | --- | --- | --- |
  | Per-field: species t^16, ability and item t^4, move t^1.5, Stat Alignment and Stat Points t | Species-first | 1 − filled/84 (today) | MD4 §6 polynomial rate, but MD4 learns the exponent per token value; fixed per field type is ours. **Control: a new per-field training on the shuffled-only table.** Today's default model (`gen84_noise_byepoch_ep80`) trained on the older table and stays as a reference only |
  | Per-field | Species-first | Corrected to the t its training used | MD4 Algorithm 2 samples with the same αₜ as training. Same checkpoint as the control, no training. Battled only if the t probe on that checkpoint reaches 0.01; on today's default model it read 0.005 |
  | Linear: every field t | Species-first | 1 − filled/84, which now matches training | MD4 App. J.1 "linear masking schedule αₜ = 1 − t"; LLaDA Eq. 3 |
  | Linear | Random | 1 − filled/84 | LLaDA Algorithm 4 (random remasking); MD4 Algorithm 2 |

  Code IDs: `sched_species_first`, `sched_species_first_t`, `sched_linear_species_first`, `sched_linear_random`.
- **The two trainings:** per-field and linear, both on the shuffled-only table `lossdata84_shuffled_only.npz`, labelled teams only (owner, 2026-11-11: "I perfer shuffled only because it only represent a win rate that is not bias by the error of the rl policy"). Both use the default model's recipe (network 256 wide, 6 layers, 8 heads; ask dropout 0.15; label noise; EMA; batch 256; learning rate 4e-4; seed 0; validation loss sets the length, patience 3, early-stopping threshold 0, cap 80, every epoch saved). Only the masking rate differs between them.
- **Shuffled-only is the default (owner, 2026-11-11: "please use only shuffle example. The default bevahior should be shuffling"):** the training code reads the shuffled-only table unless told otherwise, and an arm that reproduces a model trained on the older table stops without `--older-table` (commit `b00a71ff`). The table holds 218,978 labelled teams, each with at least 49 shuffled-slot battles. The 173,544 teams labelled only by listed-order battles or run files are not in it.
- **Guidance:** every battled row is sampled at guidance 2, 4 and 8, so each row is a three-point curve (owner, 2026-11-11: "Yes each row get three guidance value").
- **Measures, read together (owner: "holistic"):** ask-versus-got error on asks 1/24 to 17/24; win rate against the top-50 meta teams, shuffled slots, behaviour cloning on both sides; first-try legality (battles use the validator redraw); novelty (new line-ups); distinct line-ups, effective species, elite yield; the training-versus-validation gap measured with the same function on both sides (`~/vgc-data/validation_loss_accuracy/run/validation_accuracy.py`). The default model's gap is +0.0115 ± 0.0063 at epoch 80. More training seeds only if a new row performs against the win rate above.
- **Settled while charting:** per-field masking rate with random order is not a row; it already failed on this model (random decoding with lookahead: ask-versus-got error 2.5× species-first's, 2026-11-07) and on the older model (0.7% legal on first try, −0.074 win rate, 2026-10-30; remasking and lookahead did not rescue it, 2026-10-31).
- **Wording:** say **masking rate**, never noise schedule or scheduler (owner, 2026-11-11). Glossary: **Masking rate**, **Per-field masking rate**, **Linear masking rate** (added 2026-11-11).

## Decisions so far

- [Departures: where does our 84-field discrete diffusion code depart from MD4 and LLaDA?](https://github.com/Rami-Ismael/Battle-Factory-of-Porygon-Pi/issues/292): 7 of 15 parts match at least one paper, shown as a matrix in the ticket's last comment; the per-field exponents, the legal Pokémon construction filter, slot shuffling, the fixed order and the sampler's t are ours.
- [Corrected t: how should a per-field-masking-rate model be given t while decoding in a fixed order, to match MD4?](https://github.com/Rami-Ismael/Battle-Factory-of-Porygon-Pi/issues/293): give each pass the t whose expected hidden share matches training (0.650 at half hidden, against 0.500 today); our rule, modelled on MD4 Algorithm 2.
- [Pre-register the four masking-rate rows](https://github.com/Rami-Ismael/Battle-Factory-of-Porygon-Pi/issues/294): contract, probes, noise floor and storyboard are in `code/docs/masking-rate-rows.md`. The model barely reads t, 0.005 on today's default model and 0.008 on a shuffled-only model against a bar of 0.01, so Per-field, corrected t is battled only if the same probe reaches the bar on the new per-field model. The owner approved that rule ("I am fine with a prob"). Both trainings must pass early-stopping threshold 0.

- Uniform discrete diffusion, which replaces fields with random values instead of hiding them: the uniform discrete diffusion map #270.
- Regularization against overfitting: the corrected gap shows none (map #250).
