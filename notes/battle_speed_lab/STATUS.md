# Experiment status

The full goal is active. This is an implementation and measurement campaign, not a completed optimization claim.

Current evidence: `runs/bc-screen-002` is the first substantive BC-policy screen: fixed candidate and 48 meta opponents repeated twice per trial, 96 battles per measured trial, 24 in flight, five randomized ABBA/BAAB blocks for each of four changes. Every completed trial checks the requested preview base-species multiset. Mega forms require this normalization; the initial strict-form check rejected otherwise completed trials and those failed runs are excluded from comparisons by construction.

The first screen measures thread count, a 1 ms batch deadline, shared inference across both sides, and their combination. It is a warm-worker experiment, not a cold-start or multi-server scaling measurement. Its baseline reproduces the original batch-gathering algorithm with instrumentation. It does not yet quantify instrumentation overhead against an untouched worker. Early trials had substantial background activity and warm-up drift; none of the valid measured outliers are removed.

Before this screen, real-battle smoke tests exposed and corrected an event-loop ownership error in the new harness. poke-env owns a persistent background event loop. The original outer `asyncio.run` calls therefore do not mean its networking loop is recreated for every job. Worker process startup and player reconnection remain separate costs to measure.

Implemented, awaiting further validation/measurement:

- Alternate deadline-based batching, shared queues, inference thread counts, and warm workers.
- Sparse observation encoding and bounded move-feature caching. Five initial tests pass, including exact agreement with the original Pokemon encoder across 100 varied states. Live observation equality is still required.
- Actor-only inference, inference-mode execution, and full-input logit caching. These need real-input correctness tests before their performance can support a recommendation.
- Direct Showdown random-policy runner with independently seeded simulator and policy RNGs, trace-hash equality gates, and persistent/cold process comparisons. Random-policy engine results will not be presented as BC performance.
- Direct BC transport prototype using Showdown player-view streams and open team sheets, with the reference poke-env parser. Initial deterministic-mode validation is explicitly different from the stochastic production evaluator.
- Multiple private simulator groups and static/dynamic job scheduling.
