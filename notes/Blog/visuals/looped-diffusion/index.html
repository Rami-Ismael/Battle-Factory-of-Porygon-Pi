Loops inside the denoiser: five ways to give a discrete diffusion model more depth

A discrete diffusion model already works in a loop. It unmasks a few tokens, reads the result, and unmasks more. Looped models add a second loop inside each of those steps: they run the same few layers several times before they answer. This page shows the idea on a real tournament team and sorts the 2026 papers into five approaches.

Draft · 31 October 2026Sources: six arXiv papers, May to October 2026, plus one practitioner post

A diffusion model already has one loop

The from-scratch discrete diffusion model trained only on valid Pokémon teams writes a team as 48 tokens: species, item, ability, nature and four moves for each of six Pokémon. Sampling starts with every token set to [MASK]. Each denoising step runs the whole network once, predicts a token for every masked position, and keeps the predictions it is most sure of. The next step reads those kept tokens as context. Call this the outer loop: steps over time, each one a full pass through the network.

The outer loop gives every masked token the same depth. In a 12-layer model, each token gets 12 layers per step, whether it is easy or hard. Incineroar's ability is easy once the species is known. The fourth move of a support Pokémon is hard, because it depends on the other five. A standard model can put the hard token off to a later step, but it throws away the work it did on that token in this one.

A looped model adds a second loop inside each step

A looped transformer splits its layers into three groups. The head runs once and turns tokens into vectors. The looped block, a few layers in the middle, runs S times in a row with the same weights. The tail runs once and turns vectors back into token probabilities. Call the loop over the looped block the inner loop, and S the loop count. The model stores the weights of 12 layers but computes like a deeper one, and you can change S after training.

The layer split in Figure 1 is the one from the looped masked diffusion paper: 12 layers, with layers 1 and 2 (counting from 0) looped. One step then costs 1 + 2S + 9 layer passes.

Figure 1 runs both loops on MB607, a real Regulation M-B team. Thirty of its 48 tokens start masked. Pick a loop count and press Run one step. A higher count fills more tokens per step but makes each step cost more. Tick Each token leaves when ready to switch to the per-token version described in approach 3.

Two things show up at any setting. A loop count of 1 needs many cheap steps, and a loop count of 12 needs few expensive ones. The token total stays fixed, so looping changes how the work is spread out. The papers' claim is about training: a model that learns with random loop counts reaches the same validation loss with 2.3 to 3.3 times less training compute.

Five approaches to the inner loop

The papers differ on two questions. What does the loop carry: hidden states inside one step, or a state passed from one step to the next? And who decides when the loop stops: you, a convergence test, or each token? Figure 2 places each paper on those two axes. Click a paper to read how it loops.

1. Loop a middle block, choose the count at run time

The looped masked diffusion paper (LoopMDM, Lee et al., KAIST and KRAFTON) loops layers 1 and 2 of a 12-layer, 170-million-parameter masked diffusion model. During training it draws the loop count at random from 1 to 12 for every batch, so one model learns to work at every count. At equal training compute it matches the non-looped model's validation loss with 3.34 times less compute on FineWeb-Edu, 2.95 on OpenWebText and 2.34 on LM1B. On the grade-school math benchmark (GSM8K) it beats a same-size model by up to 8.5 points and a 21-layer model with the same compute per step by 3.4 points. That last result matters most: repeating two layers did better than adding nine new ones.

The looped uniform diffusion paper (Utpala et al., MBZUAI, Sony and MIT) asks whether this still works when corruption swaps tokens for random words instead of [MASK]. A uniform model cannot see which tokens are wrong, so each prediction is harder. Looping still pays: 2.8 times less training compute on OpenWebText and 3.3 on FineWeb-Edu, and up to 9.8% lower generation perplexity at the same number of steps. Its analysis found that the extra passes mostly fix the guess at replaced tokens, not the decision about which tokens to keep.

2. Loop until the block stops changing

The fixed-point masked generative model (CoFRe, Miele et al., EPFL) treats the looped block as an equation to solve: run it until its output stops changing, and use that output. The next denoising step starts the solver from the last step's answer instead of from scratch. It treats tokens three ways: an unchanged visible token reuses its old state fully, a still-masked token mostly, a newly revealed token only 20%. On OpenWebText it uses 38.8% fewer parameters than the masked diffusion baseline and, at a budget of 96 block passes, cuts generation perplexity from 193.1 to 101.8 against the distilled baseline.

3. Let each token leave the loop when it is ready

The adaptively looped diffusion model (ALoDLM, Fang, Li et al., Amazon AGI) drops the rule that every token gets the same depth. Inside one step, a token whose prediction is confident enough commits, and its embedding goes back in as context for the next pass. Tokens that are still unsure keep their hidden state and loop again. A learned exit gate decides when to stop the loop for the remaining tokens. Raising the exit threshold moves the average from 1.6 to 2.34 passes per token and the average score over eleven benchmarks from 77.9 to 79.1. At 8 billion parameters, converted from Qwen3-8B, it beats every diffusion model tested and its own autoregressive base on average, and runs about 2.7 times faster on GSM8K than Qwen3-8B served with vLLM.

4. Carry the loop's state to the next step

Self-conditioning closes a different leak. A standard sampler keeps only the sampled tokens between steps and drops the model's uncertainty. Loopholing discrete diffusion (Jo et al., ICLR 2026) passes the last hidden state forward and adds it to the next step's token embeddings. Pure self-conditioning (LAW, Deschenaux, Ilieva et al., EPFL) goes further: it passes only the expected embedding under the model's prediction and samples tokens once, at the end. On GSM8K-style problems it solves 42.2% against 34.5% for uniform Loopholing, and fine-tuning a pretrained uniform model with it lifts accuracy from 17.2% to 48.1%. The authors call this complementary to approaches 1 to 3: those change the work inside a step, this changes what crosses between steps.

5. Spend the loop budget where it pays

Both looped papers found that extra passes help most at middle noise levels, when about half the tokens are known. Very early, there is too little context to refine; very late, little is left to fix. The looped uniform paper tested three training distributions for the loop count (Figure 3). Drawing small counts more often (FLOP-proportional) matched uniform drawing at 12% fewer loops on downstream tasks. Giving noisier inputs more loops (noise-proportional) lost to both. At run time, both papers stop a step's loop once the hidden state changes by less than a set fraction between passes. LoopMDM's rule cut the average from 12 passes to about 5 and kept most of the gain.

How each paper tests its claim

Four of the five papers train small models, about 170 million parameters, from scratch on web text. Each compares the looped model with the same model without the loop, trained on the same budget of floating-point operations. A looped step costs more, so the looped model trains for fewer steps and sees fewer tokens. Every gain they report is net of that handicap. The per-token loop (ALoDLM) is the exception. It converts Qwen3 checkpoints with 5 billion tokens of fine-tuning and compares itself with models other groups released.

Which control matters depends on the claim. To show that looping beats plain depth, you need a deeper model with the same compute per step. Only LoopMDM runs that test: it gains 3.4 points over a 21-layer model. The fixed-point model holds the sampling budget equal, counted in block passes. The per-token loop holds only model size and decoding rules equal. Its closest control, WeDLM-8B, comes from the same Qwen3-8B and the same block-diffusion framework but used a different training recipe. The sections read for this page show no non-looped model trained on ALoDLM's own 5 billion tokens.

What the papers agree on

  • Loop the early-to-middle layers, not the first or the last. LoopMDM's ablation found layers 1 and 2 of 12 best. A practitioner post in the reading list reached the same rule on a 30-layer autoregressive model: loop layers 15 to 24, never the last few.
  • Train with a random loop count. One checkpoint then runs at any count, and LoopMDM kept improving past the largest count it trained on.
  • Spend loops where uncertainty is highest: middle noise levels in approach 5, hard tokens in approach 3.
  • Measure at equal compute. Every number above compares a looped model with a non-looped one trained on the same budget of floating-point operations, so the looped model saw fewer training tokens.

What this could mean for the team model

The discrete diffusion model in this project is a masked model over 48 fields, the same family as LoopMDM. Looping changes the network, not the sampler, so the masking, unmasking and loss stay as they are. The cheapest test copies approach 1: loop two early-middle layers, draw the loop count at random during training, and compare validation loss against the current model at equal training compute. Approach 3 fits the field structure well, because an ability is often fixed by the species while a fourth move depends on the whole team. None of this has been run here.
