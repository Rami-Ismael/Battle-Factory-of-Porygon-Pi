Decision Model Baseline · Champions VGC 2026 Reg Set M-B · experiment menu, 2026-10-25

Jev picks a team

A decision model does one thing. It reads a situation, looks at a list of options you wrote, and returns a probability for every option. Pokémon team building is a long run of exactly those choices. This page lists fourteen ways to test whether a decision model is good at it, and sketches the chart each test would produce.

The model under test is Jev, TypeSafe AI's decision model. It is not a language model: it never writes text, so it cannot misspell a move or invent an item. It can only pick from the list. That makes it a natural fit for the project's fill-in-the-blank task, where a team has some fields hidden and a model must fill them back in.

instructions Which item should Swampert hold?

Six of the 148 Reg M-B items. Jev returns choice (the top option), confidence, and probabilities for every option sent. The probabilities above are made up to show the shape of the answer.

from typesafe_sdk import Choice, TypeSafeClient

# Reads TYPESAFE_API_KEY. Model defaults to "jev-latest" (TYPESAFE_DEFAULT_MODEL),
# address to https://api.typesafe.ai (TYPESAFE_BASE_URL).
with TypeSafeClient() as client:
	response = client.system_one(
		state={
			"format": "Champions VGC 2026 Reg Set M-B",
			"team": partial_team,  # six slots; hidden fields are None
		},
		questions={
			"swampert_item": Choice(
				instructions="Which item should Swampert hold to do best against the meta?",
				criteria={
					"Leftovers": "Restores 1/16 max HP each turn",
					"Sitrus Berry": "Restores 1/4 max HP at half HP or less",
					# one entry per legal item, at most 255
				},
			),
		},
	)

answer = response.choices["swampert_item"]  # the same object as response.answers[...]
answer.choice         # the option with the highest probability
answer.confidence     # 0 to 1
answer.probabilities  # one value per option, summing to about 1

Code 1. Written against the SDK source at tag v0.7.5: typesafe-ai/typesafe-sdk-python 🟢 (pip install typesafe-sdk, PyPI 🟢). state takes text or a JSON object, so the partial team goes in as structured data. criteria maps each option name to a description, or to None. response.choices is response.answers filtered to Choice answers, so the two spellings in the docs both work. TYPESAFE_BASE_URL is the setting a later run would change to point the same code at another decision model.

Which blanks fit in one question

A Choice question takes at most 255 options. Some blanks fit easily, two do not, and other decision models allow far fewer. Pick a blank.

What Jev is sent

A mask becomes a chain of Choice questions, one per hidden field, asked one at a time. Each answer is written into the team before the next question, so the item question already knows which species was picked. This is the structure decided so far, written before any code exists. It will be replaced by the real printed prompt once the prompt builder is done, and you read that version before any call is sent.

Three rules sit around the questions:

  
    
    
  • Species tournament. The legal species are split at random into groups of at most 255. Jev answers one question per group, then a final between the group winners.
    • 
    
  • Four runs per mask. One takes Jev's top option at every question. Three sample each answer from Jev's probabilities. Because later questions see earlier answers, each run asks its own questions.
    • 
    
  • 32k tokens per question. The state plus one question must fit. The prompt builder counts tokens for every question and refuses a mask that doesn't fit.
    • 
  

  
Decided: Jev sees the meta. The state carries the top-50 meta teams, as Ling's prompt does, so both models know the opponents. That costs about 12k tokens per question (my estimate: 50 pastes at about 250 tokens each) and leaves about 20k of the 32k limit for the options, so species groups in the tournament are sized by tokens as well as by the 255-option limit.

Where Jev joins the scoreboard

  
Jev gets the same test every other model in this project took: the Mask Lab grids. Each grid starts from five teams, hides parts of them in 270 ways (masks), asks a model to fill each mask, rejects illegal fills, and battles every legal team against the top-50 meta teams. The score is a win rate: the share of battles the filled team wins against the top-50 meta teams, with the behaviour-cloning battle policy playing both sides.

    Other decision models
    
  
    The project runs one decision model, Jev. The code still takes the model's address, name and option limit as settings, so a later run could swap in a different one. That is realistic because many models now copy Jev's request shape (state plus named questions, served at /v1/systemone). The catch is the option limit, which ranges from 10 to 255, so the species tournament from experiment 11 stays in the code whichever model it calls.
