# Using a table to untangle temperature

Today I noticed that I was using “temperature” for several different things in my Pokémon team generator. I first wanted to add it as an experiment after discussing DiffUCO. Checking the code showed that temperature was already used in generation and in earlier retraining experiments.

I kept asking whether temperature decreases during training or whether I can change it during generation. The missing detail was **which distribution the temperature controls**. Writing that distinction as a table helped me make the question more precise.

| Method | Where it acts | What the control does | Name to use in my notes |
|---|---|---|---|
| **DiffUCO: matching a Boltzmann target** | The target distribution over complete solutions and its training objective | Temperature sets how strongly low-energy solutions are preferred. The paper decreases it during training. | **Objective temperature** |
| **Cross-entropy method (CEM)** | The outer search loop: generate, evaluate, select elites, refit, repeat | The elite fraction or score cutoff determines which evaluated teams train the next generator. Classic elite selection does not require temperature. | **Elite fraction / score cutoff** |
| **Boltzmann-weighted selection: a soft alternative to CEM’s elite cutoff** | Selecting evaluated teams for retraining in `entropyloop.py` | Temperature sets how strongly higher measured win rates affect selection probability. | **Selection temperature** |
| **Constrained sampling from the diffusion model** | Generating species, moves, items, and other choices | Temperature sets how strongly sampling favors the model’s most probable allowed choices. It can change without retraining. | **Sampling temperature** |
| **Beam search — comparison, not used in the generation paths checked** | Expanding, scoring, and retaining partial candidates at each step | Beam width sets how many candidates survive each step. It is a different control from temperature. | **Beam width** |

The intractable normalization constant belongs to the first row: it sums over all possible solutions. Temperature changes the target distribution; it does not make that sum easy to compute. [DiffUCO, sections 2–3](https://arxiv.org/html/2406.01661v1)

I had also associated generating a valid team with beam search. The code makes the actual method concrete: [the constrained sampler](/Users/ramiismael/Documents/code/vgc-team-generator-pilot/src/diffusion.py:316) fills fields in dependency order, masks disallowed choices, applies temperature to the model scores, and samples a choice with `torch.multinomial`. [The proposal loop](/Users/ramiismael/Documents/code/vgc-team-generator-pilot/src/activesearch.py:200) then checks completed teams with the Showdown validator and rejects failures. **Constraint masks and final validation handle legality; temperature controls sampling preference.** Generating a batch of teams does not itself make this beam search.

CEM sits around the generator: evaluate candidates, select stronger ones, and refit the proposal distribution. Its elite-selection controls are separate from the decoder used to generate each candidate. The code has [explicit CEM refit experiments](/Users/ramiismael/Documents/code/vgc-team-generator-pilot/src/filterrate.py:294). References: [the authors’ CEM tutorial](https://people.smp.uq.edu.au/DirkKroese/ps/aortut.pdf) and [Hugging Face’s distinction between sampling and beam search](https://github.com/huggingface/transformers/blob/main/docs/source/en/generation_strategies.md).

The separate **entropy bonus coefficient** in `entropyloop.py` changes the training loss and deserves its own name too. Likewise, the **cross-entropy loss** used to train a network is not, by itself, the **cross-entropy method** search loop.

My current todo tests **selection temperature**: fixed values, a cooling schedule, and an adaptive setting, with matched training and battle budgets. It is an adaptation of the paper’s idea. Reproducing the paper’s objective would be a separate experiment.

The habit I want to keep is simple: when one word appears in several places, make a table of **what it acts on, when it changes, and what it is meant to achieve** before adding another experiment.
