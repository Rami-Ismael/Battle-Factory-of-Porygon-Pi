# Prompt practice playground

Build the open **Skills to practice** visual around a recorded message and the reader's own next prompt. The reader must be able to inspect why a skill fits, try a revision, and review what they wrote.

## Build

1. **Prepare the cases.** For each retained practice task, record the exact starting message, its session and time, relevant reference context, the ability to practise, and an installed skill whose definition you inspected. Label excerpts and follow-ups accurately. Distinguish a transcript quotation from a quotation recovered only from a prior post. If the original message is unavailable, state that gap and use another supported case; if none remains, publish the section's missing-evidence sentence. Done when every case has a traceable original message and the skill's actual scope.

2. **Keep the source visible.** Put a case picker above a prominent original-message block. Follow it with the ability, skill name, and a short explanation of why the task calls for that skill. Distinguish an explicit slash-command invocation, a recorded skill load, and a suggested fit. An ongoing conversation can supply context that a portable exercise deliberately asks the reader to restate. Keep this comparison visible while practising. Put supporting evidence and scope details in a drawer. Done when the reader can identify the original request, source, practice goal, and skill connection before writing.

3. **Make three playable versions.** Provide a labelled button group whose choices change the exercise's workflow. Reuse these approved patterns when they fit:

   - **Prompt evolution lab:** the reader writes a goal, requested change, and observable finish. A creature grows as the reader confirms those parts. A preview combines only their own words.
   - **Prompt court:** the reader writes an observable check, selects or describes planned evidence, and writes the next prompt. Their confirmation produces a receipt of that plan.
   - **Context teleporter:** the reader names the subject and source material, writes a request for a fresh session, and inspects what that session would receive without the earlier conversation.

   Use wacky imagery to explain these actions. Distinct versions change what the reader does; color themes alone are one version. Honor a later user selection of one version to keep. Done when each offered version supports a complete practice attempt with a visible result.

4. **Let the reader revise.** Supply editable fields, optional hints, a self-review action, and reset. An edit clears any confirmation or receipt that described the previous text. Retain each case's draft when switching cases or versions. State whether reload keeps or clears drafts. Label self-review as the reader's judgement and receipts as plans. Show evaluated results only when an evaluation actually ran. Keep the default exercise local to the page. Done when the reader can write, inspect, edit, switch away and back, and reset without losing another case's work.

## Embed and verify

Embed the playground directly in the article under **Skills to practice**, open on first load. Use the daily-blog visual wrapper with a form identifier and a concise **What this visual is** explanation. A separate preview may accompany this embedded version. Treat an interactive example created during blog editing as an illustration added then, rather than work completed on the target day.

Before publishing, exercise every offered case and version in the rendered blog. Confirm that the original quote and skill explanation match the selected case; drafts survive switching; editing invalidates stale checks; hints and resets work; and user text renders as text. Test keyboard use, visible focus, touch targets at least 44 CSS pixels high, phone and desktop widths, and light and dark themes. Run the page and viewer checks required by **Page design** when that section is present in the active prompt. In every format, verify the embedded exercise in the intended reader. Record observed results separately from claims about learning or prompt quality.

Approved local example, when available: `~/vgc-data/daily-blog/2026-11-03/prompt-practice-playground.html`, with its `prompt-practice-*` source files beside it. Inspect it for layout and interaction behavior. The specification above is sufficient when this local example is unavailable. Populate each new post from its own dated evidence; the example's quotations and counts remain evidence for its original date.
